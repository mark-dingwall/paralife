    ```java
    @ConfigurationProperties(prefix = "paralife.simulation")
    public record MetabolicProfile(
        TypeProfile catalyst,
        TypeProfile membrane,
        TypeProfile spore
    ) {
        public record TypeProfile(
            int maxEnergy,
            int decayPerTick,
            int combatEnergyTransfer,
            int attackPower,
            int nutrientConsumeEnergy,
            int reproduceEnergyCost,
            int reproduceCooldown,
            double bonusOffspringChance,
            int reproduceRange,
            int starvationThreshold,
            int starvationFloor
        ) {
            public TypeProfile {
                if (maxEnergy <= 0) throw new IllegalArgumentException("maxEnergy must be > 0");
                if (decayPerTick < 0) throw new IllegalArgumentException("decayPerTick must be >= 0");
                if (attackPower < 0) throw new IllegalArgumentException("attackPower must be >= 0");
                if (combatEnergyTransfer < 0) throw new IllegalArgumentException("combatEnergyTransfer must be >= 0");
                if (nutrientConsumeEnergy < 0) throw new IllegalArgumentException("nutrientConsumeEnergy must be >= 0");
                if (reproduceEnergyCost < 0) throw new IllegalArgumentException("reproduceEnergyCost must be >= 0");
                if (reproduceCooldown < 0) throw new IllegalArgumentException("reproduceCooldown must be >= 0");
                if (reproduceRange < 1) throw new IllegalArgumentException("reproduceRange must be >= 1");
                if (bonusOffspringChance < 0.0 || bonusOffspringChance > 1.0)
                    throw new IllegalArgumentException("bonusOffspringChance must be in [0.0, 1.0]");
                if (starvationThreshold < 0 || starvationThreshold > 100)
                    throw new IllegalArgumentException("starvationThreshold must be in [0, 100]");
                if (starvationFloor < 0 || starvationFloor > starvationThreshold)
                    throw new IllegalArgumentException("starvationFloor must be in [0, starvationThreshold]");
            }

            /** Per-type child start energy: half of maxEnergy. Addresses review concern #8. */
            public int childStartEnergy() {
                return maxEnergy / 2;
            }
        }

        public TypeProfile forType(Entity.ParticleType type) {
            return switch (type) {
                case CATALYST -> catalyst;
                case MEMBRANE -> membrane;
                case SPORE -> spore;
            };
        }

        public static MetabolicProfile defaults() {
            return new MetabolicProfile(
                new TypeProfile(80, 3, 15, 15, 3, 40, 10, 0.0, 1, 30, 10),   // CATALYST
                new TypeProfile(120, 1, 5, 5, 8, 35, 8, 0.0, 1, 25, 8),      // MEMBRANE
                new TypeProfile(60, 2, 8, 8, 5, 20, 5, 0.25, 2, 35, 12)      // SPORE
            );
        }
    }
    ```

    **IMPORTANT:** `MetabolicProfile` uses prefix `paralife.simulation` which is the SAME prefix as `SimulationConfig`. Spring Boot allows multiple `@ConfigurationProperties` beans on the same prefix — they bind independently to different property subsets. `SimulationConfig` binds to `paralife.simulation.energy-decay-per-tick`, etc. while `MetabolicProfile` binds to `paralife.simulation.catalyst`, `paralife.simulation.membrane`, `paralife.simulation.spore`. There is no conflict because the field names are disjoint. If Spring complains about duplicate prefix, use `paralife.simulation.types` as a sub-prefix instead:
    ```java
    @ConfigurationProperties(prefix = "paralife.simulation.types")
    ```
    And nest the YAML under `paralife.simulation.types.catalyst`, etc. The executor should try `paralife.simulation` first and fall back to `paralife.simulation.types` if needed.
