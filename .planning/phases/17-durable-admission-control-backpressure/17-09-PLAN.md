private void onSync(Frame.SyncFrame s) {
    entityId = s.entityId();
    alive.set(true);
    state.set(BotState.initial(species));
    if (syncCount.getAndIncrement() == 0) {
        registeredLatch.countDown();
    } else {
        respawnCount.incrementAndGet();
    }
    log.info("Bot registered: entity={} species={}", entityId, species);
}

private void handleDeath() {
    alive.set(false);
    entityId = null;
    long jitter = respawnJitterMs > 0 ? rng.nextLong(respawnJitterMs) : 0L;
    long waitMs = respawnCooldownMs + jitter;
    CompletableFuture.delayedExecutor(waitMs, TimeUnit.MILLISECONDS).execute(() -> {
        Session s = this.session;
        if (s != null && s.isOpen()) {
            sendFrame(new Frame.RegisterFrame(species));   // SAME WS — death-pivot
        }
    });
}

private synchronized void sendFrame(Frame f) {
    Session s = this.session;
    if (s == null || !s.isOpen()) return;
    try {
        s.sendText(PerceptionCodec.encode(f), Callback.NOOP);
    } catch (Exception e) {
        log.warn("Failed to send frame: {}", e.getMessage());
    }
}

**STALLED-pivot vs death-pivot orthogonality (from CONTEXT D-13 / `<specifics>`):**

| Aspect | Death-pivot (Phase 15.2) | STALLED-pivot (Phase 17) |
|--------|--------------------------|--------------------------|
| Server signal | `D|<entityId>` (death frame) | `E|408|reconnect-required` (error frame) |
| WS state after | open | closed by server |
| Client action | `r|<species>` on same WS | reconnect on new WS, `r|<species>|<resumeToken>` |
| EntityId after | new (fresh respawn) | preserved (rebind to old entity) |
| Token field | unchanged | retained across reconnect, replaced by fresh token in next `S|` |

**Reconnect logic:** `BotClient` already has reconnect logic for the cold-start case (initial `connect()`). Verify by reading the file. The STALLED reconnect should reuse the same `connect()` path, but BEFORE the client sends `r|`, check whether a `resumeToken` is stored. If yes, send `r|<species>|<token>`; if no, send `r|<species>`.

**On rebind success:** the next `S|` frame carries a FRESH token. `onSync` overwrites `this.resumeToken` with that new value (consumed-once semantics).

**On rebind failure (token unknown/expired):** server falls through to fresh registration per D-13 — the next `S|` arrives with a new entityId and a new token. The client's existing `onSync` logic handles this transparently (entityId is updated, token is replaced).
