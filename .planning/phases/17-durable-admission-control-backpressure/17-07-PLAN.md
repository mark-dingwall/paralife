**Step 8 — Add `markStalled` method**

```java
public void markStalled(WebSocketSession session, long stallTick) {
    if (session == null) return;
    Object entityIdObj = session.getAttributes().get(ATTR_ENTITY_ID);
    String entityId = entityIdObj == null ? null : entityIdObj.toString();
    session.getAttributes().remove(ATTR_ENTITY_ID);
    session.getAttributes().put(ATTR_STALL_TICK, stallTick);
    if (entityId != null) {
        // Issue a resume-token grace entry so reconnect can recover the entity.
        resumeTokenRegistry.issue(entityId, session.getId(), stallTick);
    }
    // Stop further outbound to this session immediately — the queue is already saturated.
    outboundSender.detachSession(session.getId());
}
```

**Step 9 — Refactor `sendFrame` to route through OutboundSender**

```java
void sendFrame(WebSocketSession session, Frame frame) {
    if (session == null || !session.isOpen()) return;
    boolean accepted = outboundSender.offer(session.getId(), frame);
    if (!accepted) {
        // Queue full or session not attached. Fallback: synchronous send.
        // This path is rare (afterConnectionClosed window or pre-attach race);
        // direct sendMessage is acceptable here as the sender VT is gone.
        try {
            String encoded = PerceptionCodec.encode(frame);
            synchronized (session) {
                session.sendMessage(new TextMessage(encoded));
            }
        } catch (Exception e) {
            log.warn("Fallback send failed for {}: {}", session.getId(), e.getMessage());
        }
    }
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inbound WebSocket frame | Untrusted; codec validates shape (Plan 02) and AdmissionGate validates admission (Plan 03) |
| Session attributes | Server-owned; trusted reads/writes |
| Resume token in `r|` | Untrusted; equality-checked against `ResumeTokenRegistry` map |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | I — Resume-token replay | handleRegister Rebind branch | mitigate | `ResumeTokenRegistry.tryRebind` consumes the token (single-use); successful rebind issues a fresh token bound to the same entityId. Replay of the consumed token returns `Optional.empty()` → falls through to fresh registration. |
| T-17-03 | D — Slow-consumer DoS via STALLED holders | OutboundSender overflow callback → markStalled | mitigate | Overflow callback is synchronous: queue full → callback fires → `markStalled` → `outboundSender.detachSession` interrupts VT immediately. Inbound frame from a stalled session triggers `E|408|reconnect-required` then `session.close()` (Step 7 in this task). Resume-token grace expiry in Plan 05 reaps unbounded holders. |
| T-17-04 | D — Memory exhaustion via flood `r|` | sendFrame fallback path | accept | Rejection emission is bounded: each rejected `r|` produces one `ErrorFrame` (small, fixed size) routed through `OutboundSender.offer` (non-blocking). Counter increment is O(1). The fallback `synchronized(session) sendMessage` path is rare (post-detach race) and bounded by Jetty's incoming frame rate. |
| T-17-06 | T — Maintenance-flag bypass | handleRegister via AdmissionGate.evaluate | mitigate | `AdmissionGate.evaluate` is the FIRST call in handleRegister; maintenance is its FIRST guard. No path to placement bypasses the gate. |
| T-17-misc | T — STALLED → re-attach race on same Jetty session | handleTextMessage stalled-check | mitigate | The `ATTR_STALL_TICK` check returns early before any frame dispatch. Server then closes the WS — Jetty's afterConnectionClosed cleanup runs (detach OutboundSender, cleanupBot). Reconnect arrives on a NEW Jetty sessionId, so no stale ATTR_STALL_TICK leakage is possible. |
</threat_model>
