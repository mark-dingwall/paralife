<objective>
Refactor `TickBroadcaster` to enqueue tick frames and death frames via `OutboundSender.offer(...)` rather than calling `synchronized(session) { session.sendMessage(...) }`. The synchronous send blocks the tick thread on slow socket writes; the new path is non-blocking and the per-session VT (Plan 06) handles the actual transmission.

Purpose: Phase 17's core SCALE-02 promise — "slow or overloaded clients cannot drive unbounded tick drift" — requires the tick broadcaster to NEVER wait on `sendMessage`. This plan makes that change.

Output: Updated `TickBroadcaster.java` only. Plan 11 ships the integration test (full STALLED-pivot via tick broadcast saturation).
</objective>

**STALLED predicate:** `WorldWebSocketHandler` defines `ATTR_STALL_TICK` and `isStalled(attrs)` (Plan 07). To check from `TickBroadcaster` without a circular dependency, **expose a small public method** on `WorldWebSocketHandler` such as `boolean isStalled(WebSocketSession session)`, OR check the attribute directly:

```java
private static final String ATTR_STALL_TICK = "stallTick";   // duplicate constant — keep in sync; or move to a shared location
boolean stalled = session.getAttributes().containsKey(ATTR_STALL_TICK);
```

**Recommended approach:** add a small helper method on `WorldWebSocketHandler.isStalled(WebSocketSession)` and inject the handler bean. Plan 07 already exposes `markStalled(WebSocketSession, long)` as a public method — adding a sibling `isStalled` is consistent. **However:** adding a `WorldWebSocketHandler` injection to `TickBroadcaster` could create a circular dependency if `WorldWebSocketHandler` injects `TickBroadcaster` (it does NOT today — confirm by reading the file). If no cycle, the dependency is clean; if there is a cycle, fall back to attribute-checking with a constant duplicated in both classes.

**Frame size metric**: `metrics.recordFrameSize(...)` was previously called inline. After moving the encode into the OutboundSender VT, the frame size is no longer accessible at the TickBroadcaster site without re-encoding. **Two options:**
1. Drop the `recordFrameSize` call here (defer to a future plan that wires it inside OutboundSender).
2. Encode the frame in TickBroadcaster (just for size measurement), then offer the Frame to OutboundSender (which will encode again). Wasteful but preserves metrics.

**Recommended:** Option 1 — remove `recordFrameSize` calls from TickBroadcaster.onTick. If frame-size metrics are essential, **add a setter+gauge in `OutboundSender`** that records `encoded.getBytes(...).length` inside the drain loop (single place, no double-encode). Document the choice in SUMMARY. For Phase 17 minimum scope, dropping `recordFrameSize` is acceptable — the metric was never on the SCALE-01/02 critical path.
