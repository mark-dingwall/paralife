<objective>
Refactor `TickBroadcaster` to enqueue tick frames and death frames via `OutboundSender.offer(...)` rather than calling `synchronized(session) { session.sendMessage(...) }`. The synchronous send blocks the tick thread on slow socket writes; the new path is non-blocking and the per-session VT (Plan 06) handles the actual transmission.

**REVIEWS-driven changes vs initial plan:**
- **`recordFrameSize` removed (NOT dropped) — relocated to OutboundSender (codex MEDIUM).** Plan 03 added `recordFrameSize(int)` to `AdmissionMetrics`; Plan 06's `OutboundSender.drainLoop` calls it after encoding. TickBroadcaster simply does NOT measure frame size — it would require re-encoding here. The metric is preserved at the right layer.
- **STALLED predicate uses Approach A (handler helper).** Plan 07 exposes `WorldWebSocketHandler.isStalled(WebSocketSession)`. TickBroadcaster injects the handler bean. The plan still requires confirming no circular dep — `WorldWebSocketHandler` does NOT inject `TickBroadcaster` today.
- **`depends_on` adds `17-07`** because TickBroadcaster now consumes `WorldWebSocketHandler.isStalled` (added in Plan 07).

Output: Updated `TickBroadcaster.java` only. Plan 11 ships the integration test (full STALLED-pivot via tick broadcast saturation).
</objective>
