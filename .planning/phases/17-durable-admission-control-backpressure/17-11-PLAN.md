    - Boot a real Spring context with a small outbound queue (size 2) and short grace window (5 ticks).
    - Connect a BotClient and complete initial registration; capture entityId and resumeToken from S| frame.
    - Stall the session: cause queue overflow by holding the BotClient's WebSocket inbound (block its onMessage handler) while the server enqueues several tick frames.
    - Assert: server emits BACKPRESSURE stalled log marker.
    - Assert: server's next inbound frame from this stalled session yields E|408|reconnect-required and closes WS.
    - Reconnect (BotClient auto-reconnect with stored token) within grace window.
    - Assert: server emits BACKPRESSURE resumed log marker; new session re-bound to the same entityId.
    - Assert: ResumeTokenRegistry.peek(oldToken) returns empty after consumption.
    - Negative branch: stall a second session and let grace expire (advance >5 ticks). On reconnect with expired token, server falls through to fresh registration (new entityId).
  </behavior>
