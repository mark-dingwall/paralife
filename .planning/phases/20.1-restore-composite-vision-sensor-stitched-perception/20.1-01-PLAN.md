<objective>
Restore the sensory-organ perception model (D-01/D-03/D-04) inside TickBroadcaster. Replace the flat `tierOf()` authority-tier dispatch with per-role frame routing: LOCOMOTOR gets its own 8-cell adjacency stitched with the union of all SENSOR members' 5x5 windows; FEEDER/ATTACKER get 8-cell adjacency only; REPRODUCER/DEFENDER/SENSOR are passive. Omit OVERCROWDED from all composite-member frames.

Purpose: SENSOR members must produce tangible composite value (extended FOV feeding LOCOMOTOR voting) instead of acting passively. This is the foundational wire-shape change the rest of the phase builds on.

Output: Modified TickBroadcaster, updated CompositePerceptionTest, new SensorStitchedPerceptionTest. No wire/codec protocol change (MAX_S_ENTRIES=256, relative-coord ±63 are sufficient).

REVIEW NOTE (round-2 consensus, Plan 01 [MEDIUM]): four tightenings folded in — (a) an explicit any-`Coord`→LOCOMOTOR-relative (dx,dy) helper contract (SENSOR `buildCellEntries` may emit mixed `Coord.Numpad`/`Coord.Relative`), pinned by the NUMERIC-ORIGIN test; (b) a self-cell `(0,0)` filter + assertion; (c) a direct D-04 assertion on a FEEDER/ATTACKER OWN cell; (d) a MAX_S_ENTRIES bound assertion + explicit acknowledgment that the final sort supersedes the prior row-major order (intentional churn).

REVIEW NOTE (round-4 convergence, Plan 01 [BLOCKER→fixed]): the `CellEntry` signature cited in rounds 1-3 was WRONG. The 2-arg `new CellEntry(coord, envState)` does not compile; worse, the compact constructor VALIDATES `presence`↔`kind`/`envState` consistency, so even a hand-patched smaller constructor throws `IllegalArgumentException` for a nutrient cell (presence bit 0 set ⇒ kind required). The re-expression must SWAP ONLY `coord` and copy `presence`, `kind`, `entityState`, `envState` verbatim — dropping `kind`/`entityState` silently strips the nutrient/prey classification Plan 03 steers by (its tests would pass on coords while LOCOMOTOR steering to SENSOR-only food fails). Also: `envState` is `OptionalInt` (range 0..63), so D-04 assertions are `(entry.envState().orElse(0) & 0x01) == 0`. Corrected throughout below. (Also: `Coord` lives at `codec/Coord.java` not `Frame.java`; `TickFrame` fields are `curX/curY`, `Optional<StateChange> change`, `List<ActiveEffect> effects`; `Direction` is `com.paralife.engine.Direction` with `dx()/dy()` — no `.delta()`.)

REVIEW NOTE (round-3 consensus, Plan 01): five fixes folded in below. (C2) the SENSOR re-expression is pinned precisely: re-express via DIRECT `relativeTo(locoPos, absoluteCellPos)` (compute the cell's absolute position first, then one direct toroidal-shortest offset from the LOCOMOTOR — NOT a sum of two wrapped offsets, which is wrong across the seam); wrap the result in a NEW `CellEntry` as the map VALUE (reusing the SENSOR-relative original would serialize SENSOR-relative coords to the wire → broken frames); and key the dedup map on the canonical toroidal-shortest coord so the same absolute cell from two SENSORs on opposite sides of the seam dedups. A NEW cross-`dim/2` seam-wrap test pins direct `relativeTo` over offset-composition. (C3) a RUNTIME `MAX_S_ENTRIES` clamp is added to `buildLocomotorCells` (truncate after sort + single `log.warn`) so a production composite with many non-overlapping SENSORs cannot overflow the codec where no test runs; a many-SENSOR test exceeding 256 without the guard is added. (gemini) the composite Optional lookup is GUARDED with `isEmpty()` → fallback to LOCOMOTOR adjacency-only, never a blind `.get()` that crashes the tick loop. (C-DIVERGENT, operator-confirmed CLOSE-NOW) the SENSOR occupant guard additionally checks `mem.compositeId().equals(compositeId)` so a foreign composite's SENSOR at an overlapping position is NOT stitched — closing the cross-composite information-disclosure boundary; a test asserts exclusion.
