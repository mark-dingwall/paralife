<objective>
Implement D-06: replace `HeuristicBrain.decideLocomotor`'s random-shuffle ballot with a real food/threat steering heuristic that reads `frame.cells()` — including the SENSOR-derived union cells now delivered by Plan 01. The LOCOMOTOR must demonstrably vote toward food (and away from threats) that are only visible through a SENSOR.

Purpose: Close the loop — SENSOR-extended FOV is worthless unless the brain consumes it. This is the behavioural payoff of the sensory-organ model.

SCOPE HONESTY (do not under-state): this is NEW logic, not a copy/extract. `decideFullAuthority` is an EARLY-RETURNING cascade that emits ONE action with verb-switching (`A`/`E`/`M`); it does NOT produce a ranked direction list. The new helper turns prey/predator/nutrient scoring into a 3-rank IRV ballot of DIRECTIONS ONLY (predators as repulsion, prey/nutrient as attraction by -distance, top-3 DISTINCT directions). It is a genuine build behind a named helper, gated by tests, not a mechanical extraction — and crucially it produces a movement-direction ranking, NOT consume/attack action verbs (the LOCOMOTOR votes movement; full-authority A/E/M semantics must NOT be inherited literally).

Output: Modified HeuristicBrain, new HeuristicBrainLocomotorTest. Depends on Plan 01 because the LOCOMOTOR frame must already carry SENSOR union cells as Coord.Relative entries for the brain to steer by them (the unit test mocks the frame, so the dependency is semantic correctness, not a compile dependency).

ACCEPTED TECH DEBT (document in the summary; do NOT silently inherit): the reused threat/distance scoring measures distance from the LOCOMOTOR's own position. A predator adjacent to a far SENSOR (far from the LOCOMOTOR) is therefore scored as a distant, deprioritized threat — so the LOCOMOTOR will not strongly flee a predator currently eating its SENSOR. This partially undercuts the D-06 survival value of SENSORs (the SENSOR's tangible value in THIS phase is mostly food-seeking, not survival-from-distant-threat). It is accepted for this phase (prioritizing threats by proximity to ANY SENSOR cell is a follow-up); it is recorded here so it is a known limitation, not an unnoticed bug.

REVIEW NOTE (round-2 consensus, Plan 03 [LOW]): two pins folded in below — (a) the sign convention is pinned AT THE TEST with an explicit `fromDxDy(0, signum(2)) == '8'` (Coord.Relative(0,2) → north '8') assertion + comment, to stop a coordinate-sign reversal slipping through; (b) rankDirections must NOT introduce a fresh `Random` (the golden-with-actions baseline depends on the existing per-bot seed) — stated explicitly as a constraint and verified by grep. Plus the Codex note: the helper produces direction ranking, not full-authority action semantics.
