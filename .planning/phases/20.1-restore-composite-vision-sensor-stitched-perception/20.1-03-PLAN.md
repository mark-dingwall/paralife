<objective>
Implement D-06: replace `HeuristicBrain.decideLocomotor`'s random-shuffle ballot with a real food/threat steering heuristic that reads `frame.cells()` — including the SENSOR-derived union cells now delivered by Plan 01. The LOCOMOTOR must demonstrably vote toward food (and away from threats) that are only visible through a SENSOR.

Purpose: Close the loop — SENSOR-extended FOV is worthless unless the brain consumes it. This is the behavioural payoff of the sensory-organ model.

SCOPE HONESTY (do not under-state): this is NEW logic, not a copy/extract. `decideFullAuthority` is an EARLY-RETURNING cascade that emits ONE action with verb-switching (`A`/`E`/`M`); it does NOT produce a ranked direction list. Turning its prey/predator/nutrient scoring into a 3-rank IRV ballot (predators as repulsion, prey/nutrient as attraction by -distance, top-3 DISTINCT directions) is a genuine build behind a named helper, gated by tests, not a mechanical extraction.

Output: Modified HeuristicBrain, new HeuristicBrainLocomotorTest. Depends on Plan 01 because the LOCOMOTOR frame must already carry SENSOR union cells as Coord.Relative entries for the brain to steer by them (the unit test mocks the frame, so the dependency is semantic correctness, not a compile dependency).

ACCEPTED TECH DEBT (document in the summary; do NOT silently inherit): the reused threat/distance scoring measures distance from the LOCOMOTOR's own position. A predator adjacent to a far SENSOR (far from the LOCOMOTOR) is therefore scored as a distant, deprioritized threat — so the LOCOMOTOR will not strongly flee a predator currently eating its SENSOR. This partially undercuts the D-06 survival value of SENSORs. It is accepted for this phase (prioritizing threats by proximity to ANY SENSOR cell is a follow-up); it is recorded here so it is a known limitation, not an unnoticed bug.
</objective>
