# Phase 20.1 Plan 03: LOCOMOTOR rankDirections Steering — Summary

D-06 implemented: LOCOMOTOR ballot is now driven by `frame.cells()` (own adjacency + SENSOR-union cells) via a named `rankDirections` private helper, replacing the previous random shuffle. The sensory-organ FOV extension from Plan 01 now has a brain that consumes it.

## What Was Built

**`rankDirections(Frame.TickFrame, BotState, Random) → List<Direction>`** — private helper that:
- Scans `frame.cells()` classifying nutrient/prey/predator entries using `toDirectionInfo` (handles both `Coord.Numpad` and `Coord.Relative`, so SENSOR-derived dist>=2 cells participate)
- Priority: flee adjacent predator (their opposite direction first) → chase prey by -distance → move toward nutrient by -distance
- Accumulates into a `LinkedHashSet<Direction>` to deduplicate: multiple targets in the same direction collapse to one rank entry (prevents `'888'` for 5 north nutrients)
- Returns at most 3 directions; `decideLocomotor` fills remainder from `topThreeDirections(rng)` fallback skipping already-chosen directions
- Uses **only the passed-in `rng`** argument — no `new Random()` anywhere in the ranking path

**`decideLocomotor`** — rewritten to delegate to `rankDirections`, then build the 3-distinct-char ballot and emit `a|V|<3-char>`.

**`HeuristicBrainLocomotorTest`** — 8 behavioural tests:
- Sign-convention pin: `fromDxDy(0, signum(-2)) == Direction.N` + `numpadOf(N) == '8'`
- SENSOR-food-steer: nutrient at `(0,-2)` → top rank `'8'`
- THREAT-AVOID (predator-only, strengthened C5): predator at `(0,-1)` → top rank `'2'` (opposite)
- MULTI-SAME-DIRECTION DEDUP (C4): 3 north nutrients → 3 distinct ranks, top `'8'`
- Empty-frame fallback: 3 distinct `'1'..'9'` chars
- Multi-target no-dup (different directions)
- Verb `'V'` always (not A/E/M)
- Determinism: same seed → identical ballot

## Accepted Tech Debt (documented in plan)

**SENSOR-DISTANCE THREAT AVOIDANCE:** The flee gate is `adjacent(predators, 1)` (same as `decideFullAuthority`), so a predator visible only via a SENSOR (dist>=2) is NOT treated as an immediate flee threat. The LOCOMOTOR will not strongly flee a predator currently near a far SENSOR. This is intentional for Phase 20.1 — the ROADMAP success criteria require SENSOR-stitched FOV and passive wire status, not threat-via-SENSOR. The tangible D-06 value in this phase is food-seeking via SENSOR, not survival-from-distant-threat. Recorded in `rankDirections` javadoc; the THREAT-AVOID test deliberately uses dist-1 (in-scope NEAR case).
