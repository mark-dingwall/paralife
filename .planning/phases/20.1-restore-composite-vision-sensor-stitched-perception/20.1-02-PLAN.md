<objective>
Implement D-02: make the REPRODUCER role passive on the action contract and have the server auto-place its bud at the nearest free cell. Drop the `directionOf(rca.action)` dependency in `resolveReproducerBud` and replace the single direction-derived target with a bounded, deterministic, toroidal nearest-free-cell scan.

Purpose: REPRODUCER becomes a passive role (no vision, no direction choice) consistent with D-01. The server owns bud placement deterministically so the golden trace stays reproducible — including when the REPRODUCER sits next to a torus seam (the toroidal `Math.floorMod` wrap on the spawn target is what makes a seam-adjacent REPRODUCER place legally; the sort key itself needs no wrap at this radius).

Output: Modified ActionResolver, new ReproducerAutoPlaceTest. No codec/protocol change — the bot keeps sending `a|R|<numpad>`, the server simply ignores the direction arg (documented as tech debt for a later contract cleanup).

REVIEW NOTE (round-2 consensus, Plan 02 [HIGH]): the earlier "statically pre-sorted offset" optimization is DROPPED. Three reviewers flagged a `static` offset cache (frozen against the first grid dims seen in the JVM) as a latent cross-test correctness bug that buys nothing on a dormant path running once over ~120 candidates. The locked D-02 nearest-Euclidean ALGORITHM is unchanged; only the caching machinery is removed in favour of trivial per-call generate-and-sort. `static` offset caching is explicitly forbidden below.

REVIEW NOTE (round-3 consensus, claude strong-single-voice corroborated by opencode): round 2 also added a WRAPPED-offset tie-break key plus a flagship "torus-seam determinism" test. Mathematical proof: `MAX_REPRODUCER_SEARCH_RADIUS=5`, grid 16 ⇒ `dim/2=8`; for every candidate `|d| ≤ 5 ≤ 8`, `floorMod(d,16)` then normalize returns `d` UNCHANGED, so the wrapped key is byte-identical to a raw `dx²+dy², dy, dx` key at ANY placement, seam or not. The seam test therefore "cannot distinguish wrapped from raw" — it passes identically for a raw sort, i.e. it is a vacuous test (the project's own testing standard forbids "a test that always passes"), plus the wrapped normalization is dead code at this radius. Round 3 REMOVES the wrapped machinery: the sort key is plain raw `dx²+dy², dy, dx`, and the seam test is collapsed into a single honest dual-run determinism test on an edge-adjacent REPRODUCER (which still exercises the `floorMod` SPAWN wrap, just not a wrapped SORT key). This also removes the `wdx/wdy` not-effectively-final compile error opencode flagged (per-loop-iteration variables captured in a sort lambda do not compile). NB: wrapped normalization IS meaningful in Plan 01 (composite diameter approaches dim/2) — this was a Plan-02 mis-port and is removed here only.
