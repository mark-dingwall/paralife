   - Starts with `buildCellEntries(locoPos, 1, true)` — LOCOMOTOR's own 8-cell Moore ring (D-04: isCompositeMember=true)
   - Dedup map: `LinkedHashMap<Coord.Relative, CellEntry>` keyed by `Coord.Relative(dx, dy)` (value-equal, sign-safe)

   - Per SENSOR member: occupant-identity check + `role()==SENSOR` + `compositeId().equals(compositeId)` cross-composite guard (T-20.1-10)
   - Per SENSOR entry: `sensorCoordToDxDy()` → absolute cell pos → `relativeTo(locoPos, cellAbsPos)` (DIRECT, not offset-composition)

### Notes on MAX_S_ENTRIES Runtime Clamp

The `buildLocomotorCells` method includes a `subList(0, MAX_S_ENTRIES)` + single `log.warn` truncation guard after sort. This is verified **by inspection only** — it is genuinely load-bearing at the production 256×256 grid where many non-overlapping SENSORs can produce >256 union cells, but the 16×16 test grid (256 total cells) cannot construct a >256 deduped union regardless of SENSOR count. The `maxSEntriesBound` test confirms `cells().size() ≤ MAX_S_ENTRIES` but cannot trigger the truncation path. This is documented in the plan as accepted.
