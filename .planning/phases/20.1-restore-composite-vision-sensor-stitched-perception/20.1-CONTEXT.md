# Phase 20.1: Restore Composite Vision (SENSOR-stitched perception) - Context

**Gathered:** 2026-06-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Restore the SENSOR-based stitched perception that Phase 12 designed and Phase 15's protocol overhaul dropped, so SENSOR composite members produce tangible value — an extended field of view assembled from the union of SENSOR 5×5 windows, delivered to the LOCOMOTOR and consumed by its movement voting.

This phase redefines the **per-role perception model** for composite members along a "sensory-organ" theme (only SENSORs are eyes), produces the stitched vision server-side, **updates the bot HeuristicBrain to act on it**, and re-baselines the golden-trace equivalence gate.

**In scope:**
- Per-role vision model for composite members (table in D-01).
- Server-side construction of the deduplicated, deterministically-ordered SENSOR union on the LOCOMOTOR's tick frame.
- Server-side auto-placement of REPRODUCER buds (action contract change).
- HeuristicBrain consumption: LOCOMOTOR voting demonstrably acts on SENSOR-derived cells.
- Golden-trace re-baseline (new dedicated SENSOR scenario + re-pin of existing composite-bearing scenarios).
- Tests: "adding a SENSOR strictly widens (never shrinks) LOCOMOTOR's visible cells"; SENSORs stay PASSIVE on the wire; brain behavioural test.

**Out of scope:**
- Genetic/learning brains (heuristic only).
- Multi-entity-per-session multiplexing (CLAUDE.md: WS:entity 1:1 non-negotiable).
- Solo-entity perception changes beyond the OVERCROWDED simplification in D-04.

</domain>

<decisions>
## Implementation Decisions

### D-01 — Per-role vision model (the "sensory-organ" model)

A foot is not an eye. Only SENSORs are eyes; movement/action roles get minimal proprioceptive adjacency; gut/shield roles are blind.

| Role | Receives on the wire |
|------|----------------------|
| **LOCOMOTOR** | own 8-cell adjacency (radius-1) **∪ stitched SENSOR union** (full bitmask per D-03). Consumed by IRV movement voting. |
| **FEEDER** | own 8-cell adjacency only (knows when adjacent to edible food) |
| **ATTACKER** | own 8-cell adjacency only (knows when adjacent to a target) |
| **REPRODUCER** | **passive — no vision block** (see D-02) |
| **DEFENDER** | **passive — no vision block** (unchanged from today) |
| **SENSOR** | **passive receive — no vision block**; contributes its own 5×5 (radius-2) to the union (see D-03) |

- LOCOMOTOR does **not** receive a 5×5 of its own — its only first-person field is the 8-cell adjacency; all wider sight comes from SENSORs.
- The stitched union is **LOCOMOTOR-exclusive**. FEEDER/ATTACKER do **not** receive it (D-05).

### D-02 — REPRODUCER is passive; server auto-places the bud
- Timing is already server-gated on the shared pool (`ActionResolver.resolveReproducerBud` refuses unless `getSharedPoolEnergy() ≥ reproduceCost` and the pool stays above its starvation floor). Vision adds nothing to *when*.
- Drop the bot-chosen bud **direction** from the action contract. The server **auto-places** the bud at the **nearest available free cell** by Euclidean distance `sqrt(dx²+dy²)` from the REPRODUCER's own cell, searched outward on the torus (wrapped deltas).
- Rationale: a REPRODUCER sheltered in the composite interior (behind DEFENDERs) has no free adjacent cell but must still fulfil its role.
- **Planner details to lock (golden-trace needs determinism):** deterministic tie-break for equidistant cells (e.g. lowest wrapped-y then lowest wrapped-x); a bounded search radius so it never scans the whole grid; behaviour when no free cell exists within the bound (skip the bud, no error).

### D-03 — Stitched-cell fidelity
- Each SENSOR contributes a **5×5 (radius-2)** Moore window centred on its cell (matches P12 D-19 and the roadmap goal text). Multiple SENSORs union together, deduplicated by position.
- Contributed cells carry the **full bitmask** — kind + presence + `entityStatus` + `cellStatus` (toxin/mutagen/etc.) — identically to a normal vision cell, **except OVERCROWDED** (see D-04).
- The wire already supports this: variable-length `s` block, `MAX_S_ENTRIES`=256, relative coords ±63. No protocol change. Union of up to 3 SENSORs ≈ ≤75 cells, well within budget. (Members are mutually adjacent, so the ±63 relative-coord limit is never a practical constraint; planner should still clamp/assert per 15-SCHEMA §8.4.)

### D-04 — OVERCROWDED is a solo-entity-only concept
- **Omit the OVERCROWDED bit (cellStatus bit 0 = 0) from every composite-member frame** — LOCOMOTOR, FEEDER, ATTACKER alike.
- Rationale: (1) `SimulationEngine.processOvercrowding` (≈:1064) explicitly **exempts CompositeMembers** from the energy penalty; (2) composite REPRODUCER budding checks only `hasOccupant()`, not the overcrowded flag, so it gates nothing for composites either; (3) overcrowding is second-order information derivable from the visible entities the member already sees — computing and stamping it adds cost for no decision value.
- Solo **Particle / BondedPair** wire behaviour is **unchanged** — they keep the D-40 per-bot recompute. The composite-member branch is the only one that omits the bit.

### D-05 — Stitched union is LOCOMOTOR-exclusive (roadmap-prose amendment)
- The roadmap goal text says the FOV should inform "LOCOMOTOR voting **and AUTHORITY_LITE tactical decisions**." User confirmed **deviation**: only LOCOMOTOR receives the union; FEEDER/ATTACKER act on their own 8 cells. Recorded here as a deliberate amendment to the goal prose.

### D-06 — Scope includes brain consumption
- Phase 20.1 **also updates the bot `HeuristicBrain`** so LOCOMOTOR voting demonstrably steers using SENSOR-derived cells (toward food / away from threats only visible via SENSORs). Requires a behavioural test, not just wire/structural tests.

### D-07 — Golden-trace re-baseline strategy
- Add a **new dedicated golden-trace scenario** that forces a composite with ≥1 SENSOR + LOCOMOTOR and pins its own digest.
- **Additionally**, the existing composite-bearing scenarios in `GoldenTraceEquivalenceTest` **will also shift** because the LOCOMOTOR frame changes shape (5×5 → 8-cell ∪ union) and OVERCROWDED is dropped from composite frames. Those baselines must be **re-pinned** in the same plan. (Re-baseline scope is broader than "one new scenario.")

### Amendments to roadmap success criteria
- **Criterion #2 superseded:** "no-SENSOR composite retains today's FULL/AUTHORITY_LITE/PASSIVE behaviour (no regression)" no longer holds. The organ model replaces the P15 authority-tier model. A no-SENSOR composite is now **near-blind** (8-cell per active member only) — which intentionally restores P12 D-20's "strong evolutionary pressure to include a SENSOR."
- **Criteria #1, #3 (re-baseline), #4 (SENSORs PASSIVE), #5 (must land before M5) all intact.**

### Claude's Discretion
- Union ordering algorithm (must be deterministic and pinned by the golden test) — planner picks (e.g. sort by toroidal-normalized (y, x)).
- Relative-coord clamping/assert mechanics for the (non-practical) >±63 case.
- REPRODUCER nearest-free-cell tie-break and search-bound specifics (per D-02).

## Existing Code Insights

### Reusable Assets
- `TickBroadcaster.buildCellEntries()` already emits variable-length `s` blocks with relative coords and per-effect status bits — the union just feeds more cells into the same path.
- `CompositeRegistry.CompositeState` exposes `getSharedPoolEnergy()` / `getMaxPoolEnergy()` / `drainEnergy()` — REPRODUCER timing gate already lives here.
- `tierOf()` is the current per-role tier selector — the natural seam to replace with the D-01 model.
- `GoldenTraceEquivalenceTest` already forms composites (`seedAdjacentBondingPair`, forced bonding prob 1.0) — extend for the dedicated SENSOR scenario.

### Established Patterns
- Single-threaded simulation core; per-tick read-only status caches rebuilt each tick (D-41). The SENSOR union is a derived per-tick projection, same shape.
- Zero-trust vision scoping (D-40) — preserve for non-OVERCROWDED bits; D-04 removes OVERCROWDED from composite frames entirely.
- Deterministic ordering is mandatory anywhere the wire is hashed by the golden gate.

### Integration Points
- LOCOMOTOR frame: own 8-cell window unioned with SENSOR 5×5 windows before encoding.
- SENSOR coverage must be **computed but not broadcast** to the SENSOR (passive form on the wire).
- REPRODUCER action path: remove bot-direction dependency; add server-side nearest-free-cell search.
- HeuristicBrain: vote selection reads the wider `s` block (D-06).

</code_context>
