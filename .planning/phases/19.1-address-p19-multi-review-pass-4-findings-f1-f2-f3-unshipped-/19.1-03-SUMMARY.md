## Implementation Details

### Tick-Time Bound (MarkStalledTickBoundIntegrationTest)

The test computes a runtime baseline from 10 ticks before the stuck-VT scenario, then drives 10 more ticks while markStalled is running on a worker VT. The assertion:

```
bound = (baselineMaxMs == 0) ? 50 : baselineMaxMs * 5 + 20
assertThat(stalledMaxMs).isLessThanOrEqualTo(bound)
```

Rationale: 5x multiplier accommodates CI jitter while catching order-of-magnitude deadlocks (a stuck write blocks for seconds, not milliseconds). When `baselineMaxMs == 0` (very fast runner), the 50ms floor is the gate — still orders of magnitude tighter than a deadlock scenario.

### Metric Name and Description

- **Name:** `paralife.outbound.detach.timeout`
- **Description:** `OutboundSender.detachSession join timed out (drain VT did not exit within 100ms)`
- **Registered in:** `AdmissionMetrics` ctor, alongside other scalar counters
- **Incremented at:** `OutboundSender.detachSession(String)` join-timeout site, before warn log
- **Accessor:** `AdmissionMetrics.incDetachTimeout()` (public)
- **Constant:** `AdmissionMetrics.M_DETACH_TIMEOUT`
