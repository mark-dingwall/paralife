        @Test
        @DisplayName("Phase 19.1 D-20 / DR-pin — overwrite mid-drain defers to next tick (NOT dropped)")

            // Construct a unit-test ActionResolver with whatever minimal collaborators
            // it needs (mock WorldGrid, no Spring scaffolding). Pre-populate
            // pendingActions with OLD_ACTION for entity E1.
            ActionResolver resolver = newResolver();
            resolver.queueAction("E1", oldAction());

            // Simulate the tick-thread starting drainActions and capturing the
            // snapshot, BUT before it calls remove(k, OLD), the WS thread overwrites:
            //
            //   pendingActions.put("E1", NEW_ACTION)
            //
            // The cleanest way to drive this deterministically is via a hand-rolled
            // test seam OR by exposing a package-private hook. Look at how
            // ActionResolverTest exercises drainActions today (it likely has a
            // package-private accessor `pendingActions()` for assertions).
            //

            //   1) Call drainActions once normally (single value).
            //   2) Immediately call queueAction("E1", NEW_ACTION) WHILE the
            //      tick-thread "imagines" it's still mid-drain — i.e., overwrite

            //      surface ActionResolver exposes for unit testing.
            //
            // Minimum viable simulation: directly invoke a package-private helper
            // that exercises the remove(k, expected) branch.
            // ...

            resolver.simulateOverwriteAfterDrainSnapshot("E1", newAction());

            // Drain happens — old value's remove(k, expected) returns false; new
