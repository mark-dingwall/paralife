## Push-back rationale

### L1 — E5.4 @DirtiesContext is fine, keep it

Claude flagged that both test methods (`overwriteMidDrainDefersToNextTick`, `noOverwriteDrainsCleanly`) set the observer first via `setDrainObserverForD20Pin(...)`, so a stale observer cannot leak between methods.

That's correct, but the cost is negligible (two-method test class; rebuild ≈ ms in the M002 Spring context) and the annotation is belt-and-suspenders against future test additions that forget to set the observer. For a contract-pinning test where the failure mode is silent (wrong snapshot captured), the marginal cost is worth the friction reduction.

**Decision:** dismissed; keep `@DirtiesContext`.

### L3 — meterRegistry parallel-flake non-issue under forkEvery=1

OpenCode flagged `meterRegistry.counter(...)` global lookup as flaky under parallel test runs. Project memory confirms `forkEvery=1` is shipped unconditionally as of 2026-05-03 (Phase 22 test-leak audit), and the repo's testing convention is sequential JVMs per test class. The global counter cannot contend across forks because each fork has its own JVM and own MeterRegistry bean.

**Decision:** dismissed; non-applicable in this project's test runner config.
