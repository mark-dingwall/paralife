## Verified — direct evidence

### H1 verified
`GoldenTraceEquivalenceTest.java:316-333` — `seedAdjacentBondingPair` body:
```java
Entity.Particle pred = Entity.Particle.spawn(predId, predType, maxEnergy);
Entity.Particle prey = Entity.Particle.spawn(preyId, preyType, maxEnergy);
worldGrid.trySetEntity(px, py, pred);
worldGrid.trySetEntity(qx, qy, prey);
liveEntityRegistry.register(predId, new Position(px, py));
liveEntityRegistry.register(preyId, new Position(qx, qy));
// NB: no botRegistry.register(...) call
```

`19.1-05-PLAN.md:303-330` — driveScenario prescription:
```java
var liveSnapshot = liveEntityRegistry.snapshot();
for (var entry : liveSnapshot.entrySet()) {
    String sessionId = botRegistry.getSessionByEntity(entry.entityId()).orElseThrow();
    actionResolver.queueAction(sessionId, ...);
}
```

The four seed entities (`seed-pred-1`, `seed-prey-1`, `seed-pred-2`, `seed-prey-2`) appear in `liveSnapshot` but are absent from `botRegistry` — `.orElseThrow()` throws on the first iteration that hits one. Test fails on tick 0.

**Recommended fix (cheapest):** replace line 326 with
```java
botRegistry.getSessionByEntity(entry.entityId()).ifPresent(sessionId -> {
    char verb = ...;
    if (verb == 'M' || verb == 'E' || verb == 'R') totalQueuedMER++;
    actionResolver.queueAction(sessionId, ...);
});
```

The forced bonding pairs are still seeded on the grid + in `liveEntityRegistry` (their job is to force a bond formation deterministically); they simply don't get queued actions. The bond still forms via `SimulationEngine` adjacency check, which is what driveScenario was about — the actions belong to the 26 normal bots.
