## Implementation Decisions

### Block-P20 must-ship (HIGHs)

- **D-01 (F2 — codec `'B'`):** Add `case 'B':` to `PerceptionCodec.validateEventCode` switch (`PerceptionCodec.java:685`). Add a round-trip parameterised test that iterates every code declared in `Event.java` and asserts `validateEventCode` accepts it. **Why this also seeds D-15 (codec convention gate).**

- **D-02 (F1 — composite formation remap):** Replace the `unregisterByEntity` + `register` pair at the composite-formation site (`SimulationEngine.java:888`-region) with the existing `remapEntity` helper that the bond formation and dissolve sites already use. `BotRegistry.unregisterByEntity:113` always queues a `DeathNotice` — that's the spurious notice. Add a test asserting `BotRegistry.drainDeaths()` is empty after composite formation under a deterministic scenario. **Mirrors the already-working bond/dissolve sites — no new abstraction.**

- **D-03 (F3 — markDead resume-token clear):** In `WorldWebSocketHandler.markDead` (`:944-946`), read `entityId` from session attrs **before** removing `ATTR_ENTITY_ID`; pass to `ResumeTokenRegistry.clearActive(entityId)`; also remove `ATTR_RESUME_TOKEN`. Add a test asserting `tokenMap` is empty after death-without-reconnect.

- **D-04 (F4 — RNG determinism in pendingGrants):** In `EnvironmentEngine.processPendingGrants`, sort the drained `pendingGrants` collection by entityId (string compare) before invoking `randomBuff()`. CHM iteration order is non-deterministic; same-tick multi-cure currently produces different buff outcomes across runs at the same seed.

- **D-05 (CE — composite RNG determinism):** In `CompositeEnergyDistributor` (`:97,104`), snapshot `compositeRegistry.getAll()` and sort by `compositeId` before the shuffle that consumes `compositeRng`. Same root cause as D-04 (CHM iteration into seeded RNG); same fix shape.

- **D-06 (TX — ToxinPathGenerator seeded ctor):** Replace `new ToxinPathGenerator()` at `EnvironmentEngine.java:267,298` with a constructor that accepts a seed derived from `EnvironmentEngine.spawnRng` (or a dedicated `toxinRng`). Wire the same seed through `resetForTest()` so tests get bit-exact reproducibility. Mirrors the `RockGenerator` D-35 (Phase 15) pattern referenced in `19-CONTEXT.md` D-06.

- **D-07 (MS — markStalled deadlock):** In `WorldWebSocketHandler.markStalled` (`:728`), switch from `OutboundSender.detachSession(String)` to the `WebSocketSession`-typed `detachSession` overload — that overload is close-aware. Accept that the OOB 408 frame may not arrive at the client; the WS `close(SERVICE_RESTARTED)` is itself the reconnect signal (callout for client doc). Document the trade-off explicitly in code Javadoc and in `CLAUDE.md` §"Outbound concurrency". Add an integration test driving a stuck-VT scenario through markStalled and asserting tick-thread service-time stays within a small bound (e.g., < 50 ms).

### Should-ship (MEDs)

- **D-08 (AM — bucket-tag remap):** Add `AdmissionMetrics.remapBucketTags(oldEntityId, newEntityId)` helper. Call from `WorldWebSocketHandler.onEntityRemapped` (`:829-842`) alongside the existing ATTR + resume-token updates. Slow-leak fix; matters under formation churn that P20 will produce.

- **D-09 (BL — disconnect cleanup):** From `WorldWebSocketHandler.cleanupBot` (`:855-866`) and `cleanupByEntityId`, invoke `buffRegistry.unregisterEntity(entityId)`, `hooks.clearInfectionOnDeath(entityId)`, and `environmentEngine.fleeing.remove(entityId)` in addition to the existing `liveEntityRegistry.unregister`. Today these env-side states are owned by `DeathFinalizer` only — disconnect without death leaks them.

- **D-10 (FL — FLEEING transfer at composite boundaries):** Bond formation at `SimulationEngine.java:763` already calls `transferFleeing`; revert at `:1272` already covers dissolve. Missing sites: bp→cm formation (per-member `transferFleeing(bp.id(), cm.id())`) and cm→particle dissolve (`transferFleeing(cm.id(), member.id())`). Auto-expires within seconds, but cheap and complete.

### Test coverage

- **D-11 (GT — golden trace with actions):** Create `GoldenTraceWithActionsTest` (separate from existing `GoldenTraceEquivalenceTest`). Drive deterministic M/E/R/V verbs into `ActionResolver`. Pin a separate baseline digest. The existing test currently exercises no verbs (`driveScenario` queues no actions).

- **D-12 (LM — invariant test movement/reproduction):** Extend `LiveEntityRegistryInvariantTest` with movement and reproduction cases. Today it only covers AT-REST / POST-DEATH / POST-BOND / POST-COMPOSITE.

- **D-13 (EL — VT-exit assertion):** In `OutboundSenderTest.detachSessionWithSessionRefUnblocksInFlightSend`, add a package-private accessor (`OutboundSender.senderThreads()`) returning the live VT for a sessionId. Assert `t.join(2000)` succeeds and `t.isAlive() == false`. Production behaviour is correct (close-then-interrupt unblocks Jetty's write, IOException path causes loop exit on next iteration); test must observe it.

- **D-14 (L1 — detach-timeout metric):** Add a counter (e.g., `paralife.outbound.detach.timeout`) incremented in `OutboundSender.detachSession(String):154-156` alongside the existing warn log. Surface via the existing `MetricsEndpoint` registration.

- **D-15 (codec convention gate):** Round-trip parameterised test that iterates every event code from `Event.java` and round-trips through `PerceptionCodec`. Prevents future codec drift of D-01 shape.

### Doc + nits

- **D-16 (OD — `@Order` doc accuracy):** `CLAUDE.md` §Architecture currently states `PerceptionBroadcaster @Order(50) + TickBroadcaster @Order(100)`. Code has only `TickBroadcaster.java:189 @Order(50)` and there is no `PerceptionBroadcaster` class. Update `CLAUDE.md` tick-pipeline table to reflect the actual `@Order` chain. **Code is correct; only the doc is wrong.**

- **D-17 (FE — FrameEmitListener Javadoc):** Add a Javadoc warning that `FrameEmitListener` callbacks run inside `synchronized(session)` — listeners must be cheap and must not block. Doc-only; current single in-tree user is fast.

- **D-18 (FD — drainLoop close-time frame-drop comment):** Add a comment near `OutboundSender.drainLoop` documenting that frames in-queue at close are dropped by design. Doc-only.

- **D-19 (ES — entitySnapshot hoist):** In `processInteractions`, call `entitySnapshot()` once at the top, reuse the returned reference for all 3 downstream consumers. Cheap nit, ships with this phase rather than waiting on the Phase 21 perf pass.

### Declined / deferred (do NOT plan)

- **D-20 (DR — drainActions race):** DECLINED. Pass-2 M-A explicitly chose `remove(k,v)` semantics. WS-thread overwrite mid-drain leaves the *new* value in the map; next tick drains it. Bot's current-tick action defers by one tick — not lost. Comment at `ActionResolver.java:397-399` confirms intent. Reviewer misread the contract. No change.

- **D-21 (CR — concurrent registration races):** DEFER to Phase 20. Atomic check-and-place against the grid is the proper fix; needs the multiplex protocol design first. D-06 (Phase 19) explicitly tightened to single-threaded registration; system self-corrects via overcrowding penalty. Existing code comment flags the deferral.
