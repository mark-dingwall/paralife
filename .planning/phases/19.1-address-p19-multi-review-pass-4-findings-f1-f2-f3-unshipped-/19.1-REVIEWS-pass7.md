# Cross-AI Plan Review: Phase 19.1 (Pass-7)

Here is the review of Phase 19.1, assessing the plans post-pass-6 G-amendments. The plans are highly mature, surgically precise, and well-justified. The remaining risks are primarily localized to performance impacts in testing and edge cases in newly established invariants.

### Plan 01: Unshipped Fix Verification & Landing
**Summary:**
This plan surgically addresses three critical unshipped bugs (composite formation death notices, the 'B' codec omission, and resume-token leaks) and institutes a strong structural defense for the event codec.

**Strengths:**
*   **Structural Defense:** Making `Event.ALL_CODES` the single source of truth (D-15) cleanly eliminates the dual-list drift that caused the 'B' codec bug.
*   **Symmetry and Safety:** Fixes mirror existing, working analogs (e.g., `remapEntity`, `cleanupBot`), minimizing the risk of introducing novel logic bugs.

**Concerns:**
*   None. The fixes are targeted and exhaustively tested.

**Suggestions:**
*   No changes needed. The plan is sound.

**Risk Assessment:** **LOW**. Targeted, clear, and rigorously gated.

### Plan 02: Determinism Hardening
**Summary:**
Eliminates sources of non-determinism by sorting `ConcurrentHashMap` snapshots prior to RNG consumption and making the `ToxinPathGenerator` strictly stateless per-call.

**Strengths:**
*   **Comparator Totality:** The cascade logic `(entityId, initialTicks, position.x, position.y)` correctly leans on empirical invariants to enforce a total order.
*   **Statelessness:** Pinning `ToxinPathGenerator` to be completely static and stateless permanently closes a class of RNG desynchronization risks.

**Concerns:**
*   **Totality Degradation (MEDIUM):** The `PendingGrant` comparator totality relies on the `EnvironmentEngine.reduceInfection` early-return invariant. While documented with anti-reflag notes, if this invariant decays during future development, RNG non-determinism will silently return.

**Suggestions:**
*   **Active Totality Guard:** Consider adding an explicit programmatic check (e.g., asserting inequality or logging a hard warning) inside the sorting logic or simulation engine if two distinct `PendingGrant` instances ever match on all four comparator keys.

**Risk Assessment:** **LOW**. The immediate fixes are solid, but relying on implicit simulation invariants for sorting order requires vigilance.

### Plan 03: Backpressure Correctness
**Summary:**
Resolves a tick-thread deadlock under heavy load by introducing a close-aware detach session overload, adds VT-exit test assertions, and instruments detach timeouts.

**Strengths:**
*   **Deadlock Eradication:** By explicitly prioritizing the transport close to unblock Jetty's write, this plan directly eliminates the largest backpressure risk.
*   **Concurrency Coordination:** Using paired `CountDownLatch` instances in `MarkStalledTickBoundIntegrationTest` removes race-condition flakiness from a complex multi-threaded test.

**Concerns:**
*   **Shared Class State (LOW):** The `CountDownLatch never` is promoted to a test-class field. While safe under JUnit's default sequential execution, it represents shared mutable state that would cause pollution if test classes ever run in parallel.

**Suggestions:**
*   Ensure JUnit parallel execution is explicitly disabled for `OutboundSenderTest`, or refactor to use method-local latch instances with a `try-finally` block for cleanup.

**Risk Assessment:** **LOW**. Excellent integration test coverage guarantees the deadlock fix.

### Plan 04: Lifecycle Leaks
**Summary:**
Prevents slow OOMs under churn by ensuring that environment-side states (fleeing, infection, buffs) and metric tags are aggressively cleared on bot disconnect or identity remap.

**Strengths:**
*   **Placement Precision:** Relocating the `cleanupByEntityId` env-state cleanup to execute *before* the `sessionId == null` early-return fixes leaks in session-less paths.
*   **Behavioral Verification:** Shifting from grep-based assertions to single-tick behavioral testing for `FLEEING` transfers guarantees functional correctness.

**Concerns:**
*   **Manual Audit Gate (MEDIUM):** The HARD STOP instruction in Task 04b relies completely on the executor performing and interpreting a `grep` audit correctly before proceeding.

**Suggestions:**
*   Ensure the automated test suite exhaustively exercises the `markStalled` grace-window reconnect path to programmatically verify that the early-return relocation doesn't break reconnect states.

**Risk Assessment:** **LOW**. The impact is restricted to data structure cleanup, improving long-term stability.

### Plan 05: Regression Coverage + Polish
**Summary:**
A robust consolidation of testing, invariant extensions, and performance tweaks. Adds the action-driven golden trace test, drain semantics pinning, and hoists `entitySnapshot()` to save allocations.

**Strengths:**
*   **Post-Drive Sanity Probe (G1-revised):** Replacing the 50% footprint floor with strict per-verb (`>=1`) and aggregate (`>=90%`) floors correctly guards against silent payload drops without triggering flakiness on valid skips.
*   **Execution Ordering (F3/G3):** Enforcing the `processInteractions` hoist (Task 05f) to run *before* the golden-trace baseline generation (Task 05a) is a critical catch that preserves the test's validity.

**Concerns:**
*   **Test Suite Performance Penalty (HIGH):** The use of `@DirtiesContext(classMode = AFTER_EACH_TEST_METHOD)` in `ActionResolverDrainSemanticsTest` forces the entire Spring ApplicationContext to tear down and rebuild after every test method. This imposes a massive performance penalty on the integration test suite.
*   **Defensive Copy Semantics (LOW):** `Map.copyOf(snapshot)` inside the DR-pin observer creates a snapshot of a `ConcurrentHashMap` under active concurrent modification. While weakly consistent, it is safe enough for this specific test assertion.

**Suggestions:**
*   **Drop `@DirtiesContext`:** Replace `@DirtiesContext` with a simple `@AfterEach` lifecycle method that resets the observer manually (`actionResolver.setDrainObserverForD20Pin(null);`). This achieves the exact same isolation without the massive context-reloading overhead.

**Risk Assessment:** **MEDIUM**. The logic is very solid, but the test configuration (`@DirtiesContext`) poses a severe risk to CI/CD pipeline execution times.

### Overall Phase 19.1 Assessment

**Overall Risk: LOW to MEDIUM (Test Performance)**

The Phase 19.1 plans have reached an exceptionally high level of maturity following the rigorous cross-AI reviews and amendments. The B, C, D, E, F, and G amendment blocks have meticulously tightened the plans, resolving ambiguities around fake-sessions, test seam injection, and dependency ordering.

The functional code changes pose minimal risk as they mirror established, stable patterns already present in the Paralife codebase. The primary residual risk is **test suite performance degradation** due to heavy-handed context clearing mechanisms (`@DirtiesContext`), which should be optimized before execution. The phase is ready for implementation (`/gsd-execute-phase 19.1`).
