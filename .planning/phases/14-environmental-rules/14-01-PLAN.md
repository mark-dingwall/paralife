## Revision Notes (reviews cycle 4)

Cycle 4 codex/gemini review: gemini approved (LOW) subject to two BondedPair cleanup hooks; codex flagged two HIGH correctness blockers + six execution-mismatch corrections against the live source. Codex's verdict is operative per consensus summary.

**Key architectural shifts in this revision:**

1. **Bean-cycle rework (cycle-4 action item #1, HIGH).** Codex correctly pointed out that the cycle-3 `DeathCleanupHooks` interface did NOT break the Spring construction cycle — EnvironmentEngine was still wired as the DeathCleanupHooks impl, so `DeathFinalizer(DeathCleanupHooks, @Lazy SimulationEngine)` + `EnvironmentEngine(..., DeathFinalizer)` resolved back to `EnvironmentEngine → DeathFinalizer → EnvironmentEngine` at bean construction. Interface narrowing is semantic, not topological.

   **Fix (option a — preferred):** a new third bean `EnvCleanupHooksBean` is the `DeathCleanupHooks` implementation and the canonical owner of the infection / cure-immune / pending-grant maps. EnvironmentEngine and DeathFinalizer BOTH depend on this bean; neither depends on the other. The only piece of EnvironmentEngine behaviour that EnvCleanupHooksBean cannot do alone is the compost write — handled via a post-construction setter (`CompostSink`): EnvironmentEngine registers itself in its own `@PostConstruct`, so the setter runs AFTER both beans are constructed, avoiding a constructor-time cycle.

   All "interface-break solves the cycle" claims are DROPPED from the plan. The only intentional back-edge in the final graph is `SimulationEngine → DeathFinalizer → @Lazy SimulationEngine`, which is necessary so DeathFinalizer can invoke `handleMemberDeath` for same-tick composite semantics.

2. **Composite attack-path same-tick semantics (cycle-4 action item #2, HIGH — shared with 14-02 and 14-03).** Codex flagged that `EnvironmentEngine.processEnvDeaths()` runs at `@Order(14)` — BEFORE ActionResolver's composite attack path at `@Order(20)`. Toxic splash (14-02) and composite attack-cure buff grants (14-03) that fire INSIDE `resolveAttackerAttack` therefore miss both the env-death sweep AND the buff-grant drain, producing a one-tick lag that contradicts plan claims.

   **Fix (option b — preferred):** a new bean `EnvPostActionReconciler` at `@Order(25)` runs between ActionResolver(20) and PerceptionBroadcaster(50). It re-invokes `environmentEngine.processEnvDeaths()` and `environmentEngine.drainPostActionGrants()` so composite-path toxic splash deaths and composite-path cure-buff grants finalize in the same tick they fired. 14-02 and 14-03 wire their composite-path logic to use `markEnvDamageApplied()` / `pendingBuffGrants.add(...)` and rely on the reconciler for finalization. The bean is introduced HERE (14-01) because both downstream plans consume it.

3. **Test placement moved back into `com.paralife.engine` (cycle-4 action item #10).** Cycle-3 tests lived in `src/test/java/com/paralife/engine/environment/` — a subpackage that cannot see package-private helpers in `com.paralife.engine`. All env tests are now in `com.paralife.engine` with `Env*` / `Toxin*` / `Mutagen*` / `Lightning*` / `Compost*` filename prefixes. `files_modified` is updated to reflect this.

## Canonical Same-Tick Env-Death Model

**Problem 1:** SimulationEngine.processDeaths runs at @Order(10). EnvironmentEngine runs at @Order(14) and applies damage. Without intervention, a zero-energy entity produced by env damage would (a) survive the tick, (b) be picked up by ActionResolver at @Order(20), and (c) be perceived as alive by bots at @Order(50). Worse, a dead CompositeMember would leave a stale `CompositeRegistry` entry that CompositeEnergyDistributor at @Order(15) reads IMMEDIATELY.

**Problem 2 (composite-death semantics):** combat-killed composite members today run the 97/3 graceful-degradation vs dissolution roll SAME TICK inside `SimulationEngine.handleMemberDeath:695-701`. If env-death skips this roll or defers it to next tick, we silently change simulation behaviour for composite deaths — NOT a refactor.

**Problem 3 (bean cycle — cycle 4 fix):** a naive `DeathFinalizer(EnvironmentEngine)` + `EnvironmentEngine(DeathFinalizer)` construction graph is a real Spring bean cycle. The cycle-3 "narrow interface" fix did NOT break it (EnvironmentEngine was still the impl). Cycle 4 introduces a third bean — `EnvCleanupHooksBean` — as the canonical DeathCleanupHooks implementation, owning the shared infection/pending-grant state. EnvironmentEngine registers itself as the `CompostSink` collaborator via @PostConstruct so the final `applyCompost` write still executes grid mutations inside the engine, but the wiring happens post-construction.

**Problem 4 (composite attack path — cycle 4 NEW):** `ActionResolver.resolveAttackerAttack` at `@Order(20)` fires AFTER EnvironmentEngine completes its `processEnvDeaths` at `@Order(14)`. Toxic splash added inside the composite attack path (14-02) can be lethal but is not swept same-tick; composite attack-cures (14-03) enqueue `PendingGrant`s but the drain queue already ran. The cycle-4 fix adds a new `EnvPostActionReconciler` @Component at `@Order(25)` — running strictly between `ActionResolver(20)` and `PerceptionBroadcaster(50)` — that re-invokes `processEnvDeaths()` and `drainPostActionGrants()`. Same-tick semantics for composite-path env side-effects are now honest.

**Chosen approach (concise):**

- **Third bean for DI (Problem 3):** `EnvCleanupHooksBean` is the `DeathCleanupHooks` impl + canonical state owner. Neither EnvironmentEngine nor DeathFinalizer depend on the other. EnvironmentEngine registers as CompostSink in @PostConstruct.
- **Delegate-back for composites (Problem 2):** `DeathFinalizer.finalizeCompositeMemberDeath` calls `simulationEngine.handleMemberDeath(...)` via `@Lazy`. The existing 97/3 roll stays inside SimulationEngine, same tick.
- **Shared cleanup helper (Problem 2):** `SimulationEngine.handleMemberDeath` starts by calling into DeathFinalizer for per-member cleanup (bot/buff/infection/compost/clearEntity), then runs its existing member-count/roll logic unchanged.
- **Short-circuit:** `processEnvDeaths` skips the grid scan when `envDamageAppliedThisTick == false`.
- **Post-action reconciler (Problem 4 — cycle 4):** `EnvPostActionReconciler` @Order(25) re-invokes `processEnvDeaths` + `drainPostActionGrants` so composite-attack-path env side-effects finalize same tick.

**Contract (MUST be honored by Plans 02, 03, 04):**
- Env damage sites (toxin collisions, mutagen infection DoT, lightning inner-radius damage) write `entity.withEnergy(max(0, ...))` as normal AND call `environmentEngine.markEnvDamageApplied()` if the write MAY have lethaled an occupant.
- Composite-attack-path splash writes (added in 14-02 Task 4 at `ActionResolver.resolveAttackerAttack`) ALSO call `environmentEngine.markEnvDamageApplied()`. The reconciler sweeps them.
- Composite-attack-path cure grants (added in 14-03 Task 3 at `ActionResolver.resolveAttackerAttack`) enqueue their `PendingGrant` via `environmentEngine.reduceInfection(...)` — the reconciler drains them.
- They do NOT individually clear entities — they rely on `processEnvDeaths()` (either the one at the end of `EnvironmentEngine.onTick` or the one re-invoked by `EnvPostActionReconciler`) to finalise.
- `processEnvDeaths()` short-circuits when `envDamageAppliedThisTick` is false.
- When it does run, it iterates the grid once and for every occupant with `!isAlive()`:
  - Particle → `deathFinalizer.finalizeParticleDeath(x, y, p)` — shared cleanup.
  - BondedPair → `deathFinalizer.finalizeBondedPairDeath(x, y, bp)` — shared cleanup for both member ids AND bp.id() (infection cleanup on all three — cycle-4 action item #6).
  - CompositeMember → `deathFinalizer.finalizeCompositeMemberDeath(x, y, cm)` — delegates to `simulationEngine.handleMemberDeath` so the SAME 97/3 roll fires SAME TICK.

**Tests (in 14-01 Task 3 and Task 4):**
1. `EnvDeathSweepTest` (root class, default composite config): Particle env-death scenario.
2. `EnvDeathSweepTest_GracefulDegradation` (sibling class, class-level `@TestPropertySource({"paralife.composite.dissolution-chance=0.0"})`): 3-member composite → kill one → assert `removeMember` + composite survives with 2 members + composite-registry update same tick.
3. `EnvDeathSweepTest_Shatter` (sibling class, class-level `@TestPropertySource({"paralife.composite.dissolution-chance=1.0"})`): 3-member composite → kill one → assert surviving members become Particles same tick.
4. `EnvPostActionReconcilerTest`: reconciler @Order(25) is between ActionResolver(20) and PerceptionBroadcaster(50); onTick calls `processEnvDeaths` + `drainPostActionGrants` in that order.

Plans 02/03/04 each carry an acceptance criterion that says "env damage does NOT perform its own clearEntity — relies on processEnvDeaths per 14-01 same-tick model AND calls environmentEngine.markEnvDamageApplied() before the end of collision resolution. Composite-attack-path damage sites ALSO rely on EnvPostActionReconciler for same-tick finalization."

```java
package com.paralife.engine;

import com.paralife.world.Position;

/**
 * Narrow interface implemented by {@link EnvCleanupHooksBean} and consumed by
 * {@link DeathFinalizer}. The compile-time seam for the death-cleanup surface.
 *
 * <p>cycle-4 action item #1: cycle-3's "narrow interface breaks the cycle" claim
 * was wrong because Spring still wired EnvironmentEngine as the impl, leaving the
 * real construction cycle intact. Cycle 4 moves the impl to a THIRD bean
 * ({@link EnvCleanupHooksBean}) so neither EnvironmentEngine nor DeathFinalizer
 * depends on the other at construction time.
 */
public interface DeathCleanupHooks {
    /**
     * Called by DeathFinalizer when an entity dies. Implementations MUST remove
     * any env-owned state keyed by this entity id (infection map, cure-immunity
     * map, pending buff grants).
     */
    void clearInfectionOnDeath(String entityId);

    /**
     * Called by DeathFinalizer when an entity dies. Applies corpse-compost
     * nutrient bumps per D-24/D-25. Delegated to EnvironmentEngine via the
     * {@code CompostSink} collaborator registered post-construction.
     */
    void applyCompost(Position deathPos);
}
```

```java
package com.paralife.engine;

import com.paralife.world.Position;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;

import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

/**
 * Third-bean Spring component that implements {@link DeathCleanupHooks}
 * (cycle-4 action item #1).
 *
 * <p>Owns the canonical env-state maps that BOTH EnvironmentEngine and
 * DeathFinalizer need to read/write:
 * <ul>
 *   <li>{@code infections} — keyed by entity id (or BondedPair id, per 14-03)</li>
 *   <li>{@code cureImmuneUntil} — post-cure grace-period bookkeeping</li>
 *   <li>{@code pendingBuffGrants} — post-damage-alive-gated buff-grant queue</li>
 * </ul>
 *
 * <p>Infections/maps are populated by EnvironmentEngine in Plan 03. In Plan 01
 * the fields exist (so {@link #clearInfectionOnDeath} is a real no-op on empty
 * maps) but only the test fixtures write to them directly.
 *
 * <p>Compost application is delegated: EnvironmentEngine implements
 * {@link CompostSink} and registers itself on this bean via a
 * {@code @PostConstruct} call. The setter runs AFTER both beans construct, so
 * there is no bean cycle. If the sink is not yet registered (tests wiring one
 * bean at a time), {@link #applyCompost} logs and no-ops.
 */
@Component
public class EnvCleanupHooksBean implements DeathCleanupHooks {

    private static final Logger log = LoggerFactory.getLogger(EnvCleanupHooksBean.class);

    /** Setter-injected collaborator that actually mutates the grid's nutrient levels. */
    public interface CompostSink {
        void applyCompost(Position deathPos);
    }

    /** Canonical infection map — keyed by Particle id, BondedPair id, or CompositeMember id. */
    final Map<String, Object> infections = new ConcurrentHashMap<>();

    /** Canonical cure-immunity map — entity id → tick-until-expiry. */
    final Map<String, Long> cureImmuneUntil = new ConcurrentHashMap<>();

    /** Canonical post-damage buff-grant queue (type Object to avoid coupling with 14-03 PendingGrant record). */
    final List<Object> pendingBuffGrants = Collections.synchronizedList(new ArrayList<>());

    private volatile CompostSink compostSink;

    public void registerCompostSink(CompostSink sink) {
        this.compostSink = sink;
    }

    @Override
    public void clearInfectionOnDeath(String entityId) {
        infections.remove(entityId);
        cureImmuneUntil.remove(entityId);
        // pendingBuffGrants pruned by reference in Plan 03 — Plan 01 has no entries yet.
    }

    @Override
    public void applyCompost(Position deathPos) {
        CompostSink sink = compostSink;
        if (sink == null) {
            // Defensive: if tests wire this bean without an engine, skip rather than crash.
            log.debug("applyCompost called before CompostSink registered — skipping (pos={})", deathPos);
            return;
        }
        sink.applyCompost(deathPos);
    }
}
```

```java
        int y = deathPos.y();
        int maxLevel = fertilityConfig.maxLevel();
        Cell cell = worldGrid.getCell(x, y);
        int newLevel = Math.min(cell.nutrientLevel() + config.compost().fullStrength(), maxLevel);
        worldGrid.setCell(x, y, cell.withNutrientLevel(newLevel));

        for (Position neighbor : worldGrid.getNeighbors(x, y)) {
            Cell nc = worldGrid.getCell(neighbor.x(), neighbor.y());
            int nNew = Math.min(nc.nutrientLevel() + config.compost().halfStrength(), maxLevel);
            worldGrid.setCell(neighbor.x(), neighbor.y(), nc.withNutrientLevel(nNew));

    public void processEnvDeaths() {
        if (!envDamageAppliedThisTick) return;
        int w = worldGrid.getWidth(), h = worldGrid.getHeight();
        for (int x = 0; x < w; x++) {
            for (int y = 0; y < h; y++) {

                if (cell.isEmpty()) continue;
                Entity occ = cell.occupant();
                switch (occ) {
                    case Particle p -> {
                        if (!p.isAlive()) deathFinalizer.finalizeParticleDeath(x, y, p);

                    case Entity.BondedPair bp -> {
                        if (!bp.isAlive()) deathFinalizer.finalizeBondedPairDeath(x, y, bp);

                    case Entity.CompositeMember cm -> {
                        if (!cm.isAlive()) deathFinalizer.finalizeCompositeMemberDeath(x, y, cm);

                    default -> { /* Rock / Nutrient are never "dead" */ }
                }
            }
        }

        // (composite attack path) can re-trigger the sweep via the reconciler.
```

```java
package com.paralife.engine;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.context.event.EventListener;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

/**
 * cycle-4 action item #2 (Codex HIGH, 14-02 + 14-03): same-tick reconciler for
 * composite attack-path env side-effects.
 *
 * <p>Runs between {@code ActionResolver(@Order 20)} and
 * {@code PerceptionBroadcaster(@Order 50)}. ActionResolver's
 * {@code resolveAttackerAttack} (ActionResolver.java:573-627) is the site
 * where composite attacks fire — after EnvironmentEngine's own onTick at
 * @Order(14) has already completed. Without this reconciler:
 * <ul>
 *   <li>14-02 toxic splash added inside the composite attack path can be lethal
 *       but the env-death sweep already ran → splash-kills lingered to next
 *       tick.</li>
 *   <li>14-03 composite attack-cures enqueued {@code PendingGrant}s but the
 *       drain queue already ran → "receives buff immediately" was false for
 *       composite attacks.</li>
 * </ul>
 *
 * <p>The reconciler re-invokes {@link EnvironmentEngine#processEnvDeaths} (which
 * is re-entrant — the flag is toggled by composite-path damage sites) and
 * {@link EnvironmentEngine#drainPostActionGrants} in that order so composite
 * attack-path env side-effects finalize SAME TICK.
 */
@Component
public class EnvPostActionReconciler {

    private static final Logger log = LoggerFactory.getLogger(EnvPostActionReconciler.class);

    public static final int TICK_ORDER = 25;

    private final EnvironmentEngine environmentEngine;

    public EnvPostActionReconciler(EnvironmentEngine environmentEngine) {
        this.environmentEngine = environmentEngine;
    }

    @EventListener
    @Order(TICK_ORDER)
    public void onTick(TickEvent event) {
        try {
            environmentEngine.processEnvDeaths();
            environmentEngine.drainPostActionGrants();
        } catch (RuntimeException ex) {
            log.error("EnvPostActionReconciler.onTick failed at tick {} — continuing pipeline",
                    event.tickNumber(), ex);
        }
    }
}
```
