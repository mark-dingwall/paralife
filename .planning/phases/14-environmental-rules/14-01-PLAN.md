## Canonical Same-Tick Env-Death Model

(Unchanged from cycle-5 — detailed contract preserved.)

**Problem 1:** SimulationEngine.processDeaths runs at @Order(10). EnvironmentEngine runs at @Order(14) and applies damage. Without intervention, a zero-energy entity produced by env damage would (a) survive the tick, (b) be picked up by ActionResolver at @Order(20), and (c) be perceived as alive by bots at @Order(50). Worse, a dead CompositeMember would leave a stale `CompositeRegistry` entry that CompositeEnergyDistributor at @Order(15) reads IMMEDIATELY.

**Problem 2 (composite-death semantics):** combat-killed composite members today run the 97/3 graceful-degradation vs dissolution roll SAME TICK inside `SimulationEngine.handleMemberDeath:695-701`. If env-death skips this roll or defers it to next tick, we silently change simulation behaviour for composite deaths — NOT a refactor.

**Problem 3 (bean cycle — cycle 4 fix):** cycle 4 introduces a third bean — `EnvCleanupHooksBean` — as the canonical DeathCleanupHooks implementation, owning the shared infection/pending-grant state.

**Problem 4 (composite attack path — cycle 4 fix):** `EnvPostActionReconciler` @Order(25) re-invokes `processEnvDeaths()` and `drainPostActionGrants()` between `ActionResolver(20)` and `PerceptionBroadcaster(50)`. Same-tick semantics for composite-path env side-effects are honest. Plan 14-03 UPDATES the reconciler's drainPostActionGrants call to pass `event.tickNumber()` (cycle-6 HIGH #5a).

**Chosen approach (concise):**

- **Third bean for DI (Problem 3):** `EnvCleanupHooksBean` is the `DeathCleanupHooks` impl + canonical state owner. Neither EnvironmentEngine nor DeathFinalizer depend on the other. EnvironmentEngine registers as CompostSink in @PostConstruct.
- **Delegate-back for composites (Problem 2):** `DeathFinalizer.finalizeCompositeMemberDeath` calls `simulationEngine.handleMemberDeath(...)` via `@Lazy`. The existing 97/3 roll stays inside SimulationEngine, same tick.
- **Shared cleanup helper (Problem 2):** `SimulationEngine.handleMemberDeath` starts by calling into DeathFinalizer for per-member cleanup (bot/buff/infection/compost/clearEntity), then runs its existing member-count/roll logic unchanged.
- **Short-circuit:** `processEnvDeaths` skips the grid scan when `envDamageAppliedThisTick == false`.
- **Post-action reconciler (Problem 4):** `EnvPostActionReconciler` @Order(25) re-invokes `processEnvDeaths` + `drainPostActionGrants(event.tickNumber())` (cycle-6 HIGH #5a) so composite-attack-path env side-effects finalize same tick.

- Env damage sites (toxin collisions, mutagen infection DoT, lightning inner-radius damage) write `entity.withEnergy(max(0, ...))` as normal AND call `environmentEngine.markEnvDamageApplied()` if the write MAY have lethaled an occupant.
- Composite-attack-path splash writes (added in 14-02 Task 4 at `ActionResolver.resolveAttackerAttack`) ALSO call `environmentEngine.markEnvDamageApplied()`. The reconciler sweeps them.
- Composite-attack-path cure grants (added in 14-03 Task 3 at `ActionResolver.resolveAttackerAttack`) enqueue their `PendingGrant` via `environmentEngine.reduceInfection(...)` — the reconciler drains them.

package com.paralife.engine;

import com.paralife.world.Position;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;

import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

/**
 * Third-bean Spring component that implements {@link DeathCleanupHooks}
 * (cycle-4 action item #1).
 *
 * <p>Owns the canonical env-state maps that BOTH EnvironmentEngine and
 * DeathFinalizer need to read/write:
 * <ul>
 *   <li>{@code infections} — keyed by entity id (or BondedPair id, per 14-03)</li>
 *   <li>{@code cureImmuneUntil} — post-cure grace-period bookkeeping</li>
 *   <li>{@code pendingBuffGrants} — post-damage-alive-gated buff-grant queue</li>
 * </ul>
 *
 * <p>Infections/maps are populated by EnvironmentEngine in Plan 03. In Plan 01
 * the fields exist (so {@link #clearInfectionOnDeath} is a real no-op on empty
 * maps) but only the test fixtures write to them directly.
 *
 * <p>Compost application is delegated: EnvironmentEngine implements
 * {@link CompostSink} and registers itself on this bean via a
 * {@code @PostConstruct} call. The setter runs AFTER both beans construct, so
 * there is no bean cycle.
 */
@Component
public class EnvCleanupHooksBean implements DeathCleanupHooks,
        org.springframework.context.ApplicationListener<org.springframework.context.event.ContextRefreshedEvent> {

    private static final Logger log = LoggerFactory.getLogger(EnvCleanupHooksBean.class);

    /** Setter-injected collaborator that actually mutates the grid's nutrient levels. */
    public interface CompostSink {
        void applyCompost(Position deathPos);
    }

    /**
     * cycle-9 action A — fail-fast on missing CompostSink.
     *
     * <p>Spring does not guarantee {@code @PostConstruct} ordering between unrelated
     * beans. {@link EnvironmentEngine} registers itself as the sink in its
     * {@code @PostConstruct}; if that callback runs BEFORE the ApplicationContext
     * finishes refreshing and some future refactor drops the ordering, this bean
     * would silently no-op on every compost event in production. This listener fires
     * AFTER all singletons have initialized and throws loudly if the sink is still
     * null.
     *
     * <p>The runtime null-check inside {@link #applyCompost} is PRESERVED — it covers
     * test profiles (Mockito unit tests, standalone fixtures) that deliberately do
     * not register a sink.
     */
    @Override
    public void onApplicationEvent(org.springframework.context.event.ContextRefreshedEvent event) {
        if (compostSink == null) {
            throw new IllegalStateException(
                    "CompostSink was never registered — EnvironmentEngine @PostConstruct ordering regressed. "
                    + "See EnvCleanupHooksBean.onApplicationEvent() — the fail-fast check that caught this.");
        }
        log.debug("EnvCleanupHooksBean: CompostSink registered successfully at context refresh");
    }

    /** Canonical infection map — keyed by Particle id, BondedPair id, or CompositeMember id. */
    final Map<String, Object> infections = new ConcurrentHashMap<>();

    /** Canonical cure-immunity map — entity id → tick-until-expiry. */
    final Map<String, Long> cureImmuneUntil = new ConcurrentHashMap<>();

    /** Canonical post-damage buff-grant queue (type Object to avoid coupling with 14-03 PendingGrant record). */
    final List<Object> pendingBuffGrants = Collections.synchronizedList(new ArrayList<>());

    private volatile CompostSink compostSink;

    public void registerCompostSink(CompostSink sink) {
        this.compostSink = sink;
    }

    @Override
    public void clearInfectionOnDeath(String entityId) {
        infections.remove(entityId);
        cureImmuneUntil.remove(entityId);
        // pendingBuffGrants pruned by reference in Plan 03 — Plan 01 has no entries yet.
    }

    @Override
    public void applyCompost(Position deathPos) {
        CompostSink sink = compostSink;
        if (sink == null) {
            log.debug("applyCompost called before CompostSink registered — skipping (pos={})", deathPos);
            return;
        }
        sink.applyCompost(deathPos);
    }
}
