## Revision Notes (reviews cycle 3)

This revision addresses Codex HIGH cycle (`DeathFinalizer <-> EnvironmentEngine` bean cycle not solved by `@Lazy SimulationEngine`) and Codex HIGH composite-death semantics (plan silently deferred the `remaining >= 2` graceful-degradation / 3% shatter roll to next tick — a behaviour change masquerading as a refactor).

**Core changes from cycle 2 plan:**

1. **Cycle break via narrow interface (Codex HIGH):** A new interface `DeathCleanupHooks` exposes ONLY the two methods DeathFinalizer needs from EnvironmentEngine: `clearInfectionOnDeath(String)` and `applyCompost(Position)`. `DeathFinalizer` depends on `DeathCleanupHooks`; `EnvironmentEngine` implements `DeathCleanupHooks`. DeathFinalizer no longer imports EnvironmentEngine. The construction graph becomes:
   - `DeathFinalizer(WorldGrid, BotRegistry, BuffRegistry, CompositeRegistry, DeathCleanupHooks, @Lazy SimulationEngine)`
   - `EnvironmentEngine(WorldGrid, SeasonTracker, EnvironmentConfig, BuffRegistry, FertilityConfig, DeathFinalizer)`
   - `SimulationEngine(..., DeathFinalizer, ...)`
   The only remaining back-edge is `SimulationEngine -> DeathFinalizer -> (@Lazy) SimulationEngine`. `@Lazy` on the final back-edge is sufficient because it is the ONLY cycle in the graph. The prior-plan cycle (`DeathFinalizer <-> EnvironmentEngine` before `SimulationEngine` even entered the picture) is ELIMINATED, not papered over.

2. **Same-tick composite-death semantics preserved (Codex HIGH):** `DeathFinalizer.finalizeCompositeMemberDeath(x, y, cm, processedComposites)` delegates the ENTIRE decision tree back to `simulationEngine.handleMemberDeath(cm, new Position(x, y), processedComposites)` via the `@Lazy` injection. The existing 97/3 graceful-degradation vs dissolution roll at `SimulationEngine.handleMemberDeath:695-701` remains SAME TICK for env-death flows, just as it is today for combat-death flows. No silent deferral to next tick.

3. **Shared per-member cleanup helper:** `SimulationEngine.handleMemberDeath` calls a helper (conceptually: `cleanupCompositeMemberCellViaFinalizer(deadMember, deadPos)`) as its first step. That helper runs the bot/buff/infection/compost/clearEntity cleanup. THEN the existing `memberCount == 0 / memberCount == 1 / remainingCount >= 2` branch runs inline UNCHANGED. The 97/3 roll stays where it has always been: inside SimulationEngine, same-tick. Refactor, not rewrite.

4. **processEnvDeaths short-circuit (Codex MEDIUM — retained from cycle 2):** `envDamageAppliedThisTick` flag skips the full-grid scan when no env damage occurred. Damage sites in Plans 02/03/04 must call `environmentEngine.markEnvDamageApplied()`.

5. **EnvDeathSweepTest upgrade:** the composite-member scenario now sets `CompositeConfig.dissolutionChance = 0.0` so the 97/3 roll deterministically picks graceful-degradation; the assertion is that `compositeRegistry.removeMember(...)` was called AND `compositeRegistry.dissolve(...)` was NOT called (remaining count was 2, so the composite survives via graceful-degradation with 2 members — same-tick, via the SAME inline code path combat uses today).

## Canonical Same-Tick Env-Death Model (Codex HIGH composite + cycle)

**Problem 1:** SimulationEngine.processDeaths runs at @Order(10). EnvironmentEngine runs at @Order(14) and applies damage. Without intervention, a zero-energy entity produced by env damage would (a) survive the tick, (b) be picked up by ActionResolver at @Order(20), and (c) be perceived as alive by bots at @Order(50). Worse, a dead CompositeMember would leave a stale `CompositeRegistry` entry that CompositeEnergyDistributor at @Order(15) reads IMMEDIATELY.

**Problem 2 (Codex HIGH composite):** combat-killed composite members today run the 97/3 graceful-degradation vs dissolution roll SAME TICK inside `SimulationEngine.handleMemberDeath:695-701`. If env-death skips this roll or defers it to next tick, we silently change simulation behaviour for composite deaths — NOT a refactor.

**Problem 3 (Codex HIGH cycle):** a naive `DeathFinalizer(EnvironmentEngine)` + `EnvironmentEngine(DeathFinalizer)` construction graph is a real Spring bean cycle. `@Lazy SimulationEngine` does not solve it because the cycle exists before SimulationEngine enters the picture.

**Chosen approach:**

- **Narrow interface (Problem 3):** `DeathCleanupHooks` isolates the only EnvironmentEngine capability DeathFinalizer needs (compost + infection cleanup). EnvironmentEngine implements it. DeathFinalizer does not import EnvironmentEngine.
- **Delegate-back for composites (Problem 2):** `DeathFinalizer.finalizeCompositeMemberDeath` calls `simulationEngine.handleMemberDeath(...)` via `@Lazy`. The existing 97/3 roll stays exactly where it is — SimulationEngine, inline, same tick.
- **Shared cleanup helper (Problem 2):** `SimulationEngine.handleMemberDeath` starts by calling into DeathFinalizer for per-member cleanup (bot/buff/infection/compost/clearEntity), then runs its existing member-count/roll logic unchanged.
- **Short-circuit (Codex MEDIUM):** `processEnvDeaths` skips the grid scan when `envDamageAppliedThisTick == false`.

**Contract (MUST be honored by Plans 02, 03, 04):**
- Env damage sites (toxin collisions, mutagen infection DoT, lightning inner-radius damage) write `entity.withEnergy(max(0, ...))` as normal AND call `environmentEngine.markEnvDamageApplied()` if the write MAY have lethaled an occupant.
- They do NOT individually clear entities — they rely on the `processEnvDeaths()` sweep at the end of EnvironmentEngine.onTick to finalise.
- `processEnvDeaths()` short-circuits when `envDamageAppliedThisTick` is false (Codex MEDIUM).
- When it does run, it iterates the grid once and for every occupant with `!isAlive()`:
  - Particle → `deathFinalizer.finalizeParticleDeath(x, y, p)` — shared cleanup (no composite decisions to make).
  - BondedPair → `deathFinalizer.finalizeBondedPairDeath(x, y, bp)` — shared cleanup for both member ids.
  - CompositeMember → `deathFinalizer.finalizeCompositeMemberDeath(x, y, cm)` — delegates to `simulationEngine.handleMemberDeath(cm, new Position(x, y), new HashSet<>())` so the SAME 97/3 roll fires SAME TICK as it would for a combat kill.

**Test (in 14-01 Task 3):** `EnvDeathSweepTest` contains three assertions:
1. Particle env-death: place Particle, call `env.killParticleAtForTest(x,y)`, call `env.processEnvDeathsForTest()` → assert `grid.getCell(x,y).isEmpty()` AND `botRegistry.getBySession(sessionId).isEmpty()`.
2. CompositeMember env-death (graceful degradation path): `CompositeConfig.dissolutionChance = 0.0`, create 3-member composite, call `env.killCompositeMemberAtForTest(...)`, call `env.processEnvDeathsForTest()` → assert `compositeRegistry.removeMember(...)` was called AND the composite still exists with 2 members (no silent deferral).
3. CompositeMember env-death (shatter path): `dissolutionChance = 1.0`, create 3-member composite, call kill + sweep → assert dissolveToParticles was invoked same tick (verify via member occupants becoming Particles in the grid).

Plans 02/03/04 each carry an acceptance criterion that says "env damage does NOT perform its own clearEntity — relies on processEnvDeaths per 14-01 same-tick model AND calls environmentEngine.markEnvDamageApplied() before the end of collision resolution."

/**
 * Canonical death-cleanup service.
 *
 * <p><b>Cycle break (Codex HIGH cycle 3):</b> this class depends on
 * {@link DeathCleanupHooks} — a narrow interface — rather than on
 * {@link EnvironmentEngine} directly. The construction graph therefore no
 * longer contains a {@code DeathFinalizer <-> EnvironmentEngine} cycle. The
 * only remaining back-edge is {@code SimulationEngine -> DeathFinalizer ->
 * (@Lazy) SimulationEngine}, which is the minimum necessary to allow
 * DeathFinalizer to call {@link SimulationEngine#handleMemberDeath} for the
 * same-tick composite-death decision tree.

 * {@link #finalizeCompositeMemberDeath} does NOT reimplement the composite
 * decision tree. It delegates entirely to
 * {@link SimulationEngine#handleMemberDeath}, which performs the shared
 * per-member cleanup as its first step and then runs the existing
 * {@code memberCount == 0 / == 1 / >= 2} branches and the 97/3
 * graceful-degradation vs dissolution roll inline. Behaviour is identical for
 * combat- and env-caused composite deaths.
 *
 * <p>For Particle and BondedPair deaths there is no decision tree, so this
 * class performs the cleanup steps directly (bot + buff + infection + compost
 * + clear-cell) via the shared hooks.
 */
@Component
public class DeathFinalizer {

    private static final Logger log = LoggerFactory.getLogger(DeathFinalizer.class);

    private final WorldGrid worldGrid;
    private final BotRegistry botRegistry;
    private final BuffRegistry buffRegistry;
    private final CompositeRegistry compositeRegistry;
    private final DeathCleanupHooks hooks;
    private final SimulationEngine simulationEngine;

    public DeathFinalizer(WorldGrid worldGrid,
                          BotRegistry botRegistry,
                          BuffRegistry buffRegistry,
                          CompositeRegistry compositeRegistry,
                          DeathCleanupHooks hooks,
                          @Lazy SimulationEngine simulationEngine) {
        this.worldGrid = worldGrid;
        this.botRegistry = botRegistry;
        this.buffRegistry = buffRegistry;
        this.compositeRegistry = compositeRegistry;
        this.hooks = hooks;
        this.simulationEngine = simulationEngine;
    }

    public void finalizeParticleDeath(int x, int y, Particle p) {
        botRegistry.unregisterByEntity(p.id());
        buffRegistry.unregisterEntity(p.id());
        hooks.clearInfectionOnDeath(p.id());
        hooks.applyCompost(new Position(x, y));
        worldGrid.clearEntity(x, y);
    }

    public void finalizeBondedPairDeath(int x, int y, BondedPair bp) {
        botRegistry.unregisterByEntity(bp.primaryEntityId());
        botRegistry.unregisterByEntity(bp.secondaryEntityId());
        buffRegistry.unregisterEntity(bp.primaryEntityId());
        buffRegistry.unregisterEntity(bp.secondaryEntityId());
        hooks.clearInfectionOnDeath(bp.primaryEntityId());
        hooks.clearInfectionOnDeath(bp.secondaryEntityId());
        hooks.applyCompost(new Position(x, y));
        worldGrid.clearEntity(x, y);
    }

    /**
     * CompositeMember death — delegates entirely to
     * {@link SimulationEngine#handleMemberDeath} so the existing same-tick
     * 97/3 graceful-degradation / dissolution roll (lines 695-702) runs
     * exactly as it does for combat-killed composite members.
     *
     * @param processedComposites caller-scoped set to prevent double-processing.
     *                            Env-death callers typically pass
     *                            {@code new HashSet<>()} via the convenience
     *                            overload; SimulationEngine's own processDeaths
     *                            loop passes its existing sweep-scoped set.
     */
    public void finalizeCompositeMemberDeath(int x, int y, CompositeMember cm,
                                              Set<String> processedComposites) {
        simulationEngine.handleMemberDeath(cm, new Position(x, y), processedComposites);
    }

    /** Convenience overload for env-death callers. */
    public void finalizeCompositeMemberDeath(int x, int y, CompositeMember cm) {
        finalizeCompositeMemberDeath(x, y, cm, new HashSet<>());
    }
}

        worldGrid.setCell(x, y, cell.withNutrientLevel(newLevel));

            int nNew = Math.min(nc.nutrientLevel() + config.compost().halfStrength(), maxLevel);
            worldGrid.setCell(neighbor.x(), neighbor.y(), nc.withNutrientLevel(nNew));

     * DeathFinalizer; composite-member env-deaths therefore trigger
     * {@link SimulationEngine#handleMemberDeath} with its existing same-tick
     * 97/3 roll. Short-circuits when no env damage ran.

    void processEnvDeaths() {
        if (!envDamageAppliedThisTick) return;
        int w = worldGrid.getWidth(), h = worldGrid.getHeight();
        for (int x = 0; x < w; x++) {
            for (int y = 0; y < h; y++) {
                Cell cell = worldGrid.getCell(x, y);
                if (cell.isEmpty()) continue;
                Entity occ = cell.occupant();
                switch (occ) {
                    case Particle p -> {
                        if (!p.isAlive()) deathFinalizer.finalizeParticleDeath(x, y, p);

                        if (!bp.isAlive()) deathFinalizer.finalizeBondedPairDeath(x, y, bp);

                        // via DeathFinalizer — same-tick 97/3 roll preserved.
                        if (!cm.isAlive()) deathFinalizer.finalizeCompositeMemberDeath(x, y, cm);
                    }
                    default -> { /* Rock / Nutrient are never "dead" */ }
                }
            }
        }
    }

        }
    }
