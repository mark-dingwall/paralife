## Revision Notes (reviews cycle 3)

This revision addresses Codex HIGH cycle 3 on 14-06: the cycle-2 harness was not actually deterministic, `WorldGrid.clearEntity()` leaks env state across runs, and BotClient instrumentation is scope creep.

**Core changes from cycle 2 plan:**

1. **Determinism scoped to env-only components (Codex HIGH cycle 3).** `SimulationEngine.processInteractions` (`src/main/java/com/paralife/engine/SimulationEngine.java:141`) uses `ThreadLocalRandom.current()` for shuffle at line 154, combat at multiple sites, bonding decisions, and composite dissolution rolls. Reseeding ONLY `EnvironmentEngine.rng` from `config.seed()` cannot make a full-pipeline tick loop deterministic — the non-env sites use an unreseedable thread-local RNG.

   **Fix:** add a public `EnvironmentEngine.onTickEnvOnlyForTest(long tickNumber)` method that runs ONLY the env-owned tick phases:

   ```java
   public void onTickEnvOnlyForTest(long tickNumber) {
       // Mirrors onTick(TickEvent) but bypasses SimulationEngine / ActionResolver.
       cellStatusCache.clear();
       entityStatusCache.clear();
       envDamageAppliedThisTick = false;
       if (!config.enabled()) return;
       Season season = seasonTracker.getSeason(tickNumber);
       try {
           rollPoissonEvents(tickNumber, season);
           advanceActiveEvents(tickNumber);
           resolveEnvEntityCollisions(tickNumber);
           tickBuffsAndInfections(tickNumber);
           processEnvDeaths();
           buildStatusCaches(tickNumber);
       } catch (RuntimeException ex) {
           log.error("onTickEnvOnlyForTest failed at tick {}", tickNumber, ex);
       }
   }
   ```

   The determinism test calls THIS in its driveRun loop (not `publisher.publishEvent(new TickEvent(tick))`). The fields reset in `resetForTest()` + the env-only tick path use only `environmentEngine.rng` (plus the `rng` passed to `ToxinPathGenerator.generatePath`, which is already derived from `environmentEngine.rng`). Two runs with the same seed produce identical observables — because no unreseeded RNG is touched.

   The cycle-2 plan's claim that the full-pipeline loop would be deterministic was wrong. The cycle-3 fix makes the test scope honest: "deterministic ENV engine" — not "deterministic whole simulation".

2. **`WorldGrid.clear()` replaces `WorldGrid.clearEntity()` in `resetAll()` (Codex HIGH cycle 3).** `WorldGrid.clearEntity(x,y)` (verified at `src/main/java/com/paralife/world/WorldGrid.java:106`) calls `cells[x][y] = cells[x][y].cleared()` which preserves `nutrientLevel` and `flags`. Applying compost (D-24) in run A would leave elevated nutrient values on the grid that run B sees at tick 1 — not a deterministic starting state. `WorldGrid.clear()` (at line 121) resets EVERY cell to `Cell.EMPTY` — full wipe including nutrients and flags. `resetAll()` now uses `worldGrid.clear()` and explicitly reseeds any baseline fertility/nutrient state the test cares about (in practice, tests seed entities with default-empty cells, so no additional fertility reseeding is needed).

3. **No BotClient instrumentation — reuse PerceptionActionIntegrationTest pattern (Codex HIGH cycle 3).** The cycle-2 plan proposed adding a `TestInstrumentedBotClient` subclass or a callback hook. BotClient has no existing override seam, so adding one is scope creep for a single smoke test. Instead, `EnvironmentFullStackSmokeTest` reuses the raw-WebSocket pattern already shipped in `PerceptionActionIntegrationTest` (`src/test/java/com/paralife/engine/PerceptionActionIntegrationTest.java:73-97`): `StandardWebSocketClient` + a local `TextWebSocketHandler` subclass that parses incoming JSON and enqueues `Messages.Perception` payloads into a `BlockingQueue`. The test drains the queue and checks for non-zero status bytes. No change to `BotClient`.

All other cycle-2 fixes (reset hooks covering every env-owned field, DeathFinalizer death-event counter, @TestPropertySource per class, split engine-only / wire-path structure) are preserved unchanged.
