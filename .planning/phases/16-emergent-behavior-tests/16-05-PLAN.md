```java
private record RunObservables(int compositeCount, double bondedPairCounterDelta, double compositeCounterDelta) {}

private RunObservables driveRun(int ticks) {
    double bondBefore = emergenceMetrics.bondedPairsFormed();
    double compositeBefore = emergenceMetrics.compositesFormed();

    // Seed the grid with BondedPair-eligible particles in deterministic positions.
    // Exact shape (5-10 adjacent C+M pairs at pinned coords) calibrated to produce
    // at least one composite in the tick budget. Derive positions from the master
    // seed only via the already-seeded beans — placement here is the fixed scenario.
    seedDeterministicScenario();

    for (long t = 1; t <= ticks; t++) {
        publisher.publishEvent(new TickEvent(t));     // synchronous dispatch — drives @Order(10..200) listeners
    }

    double bondAfter = emergenceMetrics.bondedPairsFormed();
    double compositeAfter = emergenceMetrics.compositesFormed();
    return new RunObservables(
            compositeRegistry.size(),
            bondAfter - bondBefore,
            compositeAfter - compositeBefore);
}

    // Inspiration: CompositeFormationTest's setup — copy whatever positions + energies it uses.
```

**Step 4 — The three test methods (VALIDATION.md §Meta-validation #1 + #3):**

```java
@Test
void compositeFormationIsDeterministicAcrossThreeRunsWithSameSeed() {
    List<RunObservables> observations = new ArrayList<>();
    int runs = 3;
    int ticks = 200;
    for (int r = 0; r < runs; r++) {
        resetAll();
        observations.add(driveRun(ticks));
    }

    Set<Integer> uniqueCompositeCounts = new HashSet<>();
    for (RunObservables o : observations) uniqueCompositeCounts.add(o.compositeCount());

    assertThat(uniqueCompositeCounts)
        .as("seed=42 — all %d runs must produce identical compositeRegistry.size()", runs)
        .hasSize(1);

    // Sanity: at least one composite actually formed, else the test proves "zero is zero"
    assertThat(observations.get(0).compositeCount())
        .as("If this is 0, seedDeterministicScenario is under-tuned or forced-composite config is too weak")
        .isGreaterThan(0);
}

@Test
```

**Decision on the two-seed negative control:** Put the second-seed class as a sibling static-class inside this file, with its own `@SpringBootTest` + `@TestPropertySource` using `seed=1337` across all five seed keys. Inside that class, assert composite count across 3 runs is internally identical (hasSize(1)) — but ALSO, per VALIDATION meta-validation #3 intent, require that this count is *recorded* so the outer test or a third-party comparison can prove seed-42 ≠ seed-1337.

Simplest correct shape — two independent `@SpringBootTest` classes with a shared `@Tag("determinism")`:

File `CompositeFormationDeterminismTest.java` — owns the seed=42 class.
File `CompositeFormationDeterminismTest.java`'s nested static class `DifferentSeedSibling` — seed=1337, same scenario.

AssertJ tests in each: `assertThat(new HashSet<>(compositeCounts)).hasSize(1);`.

Then a third test method in the outer class compares (relies on both nested classes having run first — ordering-sensitive; fragile). **Final chosen shape to avoid ordering fragility**:

- Outer test class: seed=42, @DirtiesContext per method. Has `sameSeedIdentity` (3-run HashSet.hasSize(1)) + `nonZeroCompositeCount` (seeded run produces > 0 composites — negative control against always-zero).
- Note in javadoc: "Full cross-seed divergence control deferred to 16-06 long-run calibration (seed-varied runs logged in fixtures/run-*.json)."

Rationale: the real negative control for D-04/R15 is "at least one composite formed under seeded run" (catches always-zero false-pass). Different-seed-produces-different-count is lower-value within-plan — the variance matters more in the long-run test.

**So the final test methods are:**

1. `compositeFormationIsDeterministicAcrossThreeRunsWithSameSeed()` — 3 runs, HashSet hasSize(1) on `compositeCount`. Also asserts `bondedPairCounterDelta > 0` across runs (consistency signal — all runs produce the same counter delta, not just the same registry size).
2. `seededRunProducesAtLeastOneComposite()` — single run, `compositeCount > 0`. Negative control against the always-zero false-pass mode.
3. `emergenceMarkersFireDuringSeededRun()` — run once, attach `TestLogCapture` (16-04), assert `logCapture.emergenceMarkers()` contains at least one `"EMERGENCE bonded-pair-formed"` line AND at least one `"EMERGENCE composite-formed"` line. Proves the D-15 log markers land alongside the counters.
