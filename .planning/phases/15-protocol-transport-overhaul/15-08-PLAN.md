    Full rewrite of the per-bot projection step inside `onTick`. Structure:

    ```java
    @EventListener
    @Order(50)
    public void onTick(TickEvent event) {
        Iterable<BotRegistry.BotEntry> bots = botRegistry.getAllBots();
        for (BotRegistry.BotEntry bot : bots) {
            WebSocketSession session = sessionRegistry.getSession(bot.sessionId());
            if (session == null || !session.isOpen()) continue;
            try {
                Frame.TickFrame frame = buildTickFrame(bot, event.tick());
                String encoded = PerceptionCodec.encode(frame);
                synchronized (session) {
                    session.sendMessage(new TextMessage(encoded));
                }
            } catch (Exception e) {
                log.warn("Failed to send tick to {}: {}", bot.sessionId(), e.getMessage());
            }
        }
    }
    ```

    Implement `buildTickFrame`:

    1. Determine authority tier from the bot's entity kind + role:
       - Solo Particle / BondedPair / composite LOCOMOTOR → `full`; sensorRadius = 2 (3 with SENSOR_PLUS_1).
       - composite FEEDER / ATTACKER / REPRODUCER → `authority-lite`; sensorRadius = 1.
       - composite SENSOR / DEFENDER → `passive`; use Frame.TickFrame minimal form (sensorRadius = 0 signals minimal per our record convention in plan 15-02).

    2. Build positional header:
       - `tickId` = event.tick().
       - `(curX, curY)` = entity's absolute world position from `WorldGrid.findEntity(id)` or similar.
       - `(energy, maxEnergy)` from the Particle/CompositeMember record.
       - `sensorRadius` per tier.

    3. For full / authority-lite: build `cells` list by iterating the NxN vision window, skipping self. Per cell:
       - Determine `presence` by whether occupant is present AND/OR env state is non-zero.
       - Encode kind char via SCHEMA §8.1.1 mapping (use a `switch` over Entity sealed subtypes — NEVER emit the entity id).
       - Bonded pair: emit `D`/`N`/`T` based on PRIMARY type only. Secondary is hidden (SCHEMA §9 D-28 stricter zero-trust).
       - Composite member: emit role digit '0'-'5' derived from role enum.
       - `entityState` from `environmentEngine.getEntityStatus(occupant.id())` — SERVER side lookup; the id never crosses the wire.
       - `envState` from the preserved mask-and-OR block:
         ```java
         byte cached = environmentEngine != null ? environmentEngine.getCellStatus(cellPos) : (byte) 0;
         byte perBotOvercrowdedBit = computeVisionScopedOvercrowded(...) ? BIT_OVERCROWDED : 0x00;
         byte cellStatus = (byte) ((cached & ~BIT_OVERCROWDED) | perBotOvercrowdedBit);
         ```
         This EXACT expression is preserved from plan 15-07.

    4. RLE runs: for consecutive rocks along a numpad direction (E/N/S/W/NE/SE/NW/SW), combine into one `RockRun(direction, additionalCount)` entry. Apply only when no env state differs across the run; otherwise emit individual `RockSolo` + env-only supplement entries per SCHEMA §8.1 note.

    5. `change` (c block): set Optional.of(StateChange(code, ctx)) if this tick triggered a bond/composite transition for this entity. Ctx carries new maxEnergy (for bonded primary) or primary entityId (for bonded secondary).

    6. `effects` (f block): from BuffRegistry + EnvironmentEngine infection + FLEEING injection:
       - For each ActiveBuff(BuffType, expiryTick) for this entity: map BuffType → code:
         - `SENSOR_PLUS_1` → 'S'
         - `ATTACK_PLUS_1` → 'A'
         - `MOVEMENT_PLUS_1` → 'M'
         - `UPKEEP_MINUS_1` → 'U'
       - If entity is in `EnvironmentEngine.infections`: emit `I:<expiryTick>`.
       - If FLEEING was applied this tick: emit `F:<expiryTick>:<XXYY>` where XXYY is abs strike coord. The FLEEING applier lives in EnvironmentEngine (Task 2 below).

    7. `events` (v block): collect for this bot from the tick's event queue:
       - `E<numpad><magnitude>` when this bot consumed a nutrient.
       - `A<numpad><magnitude>` when it dealt attack damage.
       - `H<numpad><magnitude>` when it received combat damage.
       - `T<magnitude>` when it took toxin damage.
       - `M<magnitude>` mutagen tick damage.
       - `R<magnitude>` reflection/splash damage.
       - `L<coord><magnitude>` lightning hit (SCHEMA §9 lightning is now event, not far-perception).
       - `N<coord>` alarm from composite member (LOCO-only).
       - `S` reproduction success.
       - `D` died (terminal).

    8. `pool` (p block): for full-authority LOCOMOTOR in a composite, include PoolSnapshot(pool, maxPool). Omit for solo/bonded/authority-lite/passive.

    9. `roster` (g block): for LOCOMOTOR only, include RosterMember list WHEN the roster changed since the last tick sent to this bot. Track last-sent-roster per bot in a field Map<sessionId, rosterHash>. Rosters are small; exact comparison is fine.

    Remove `ObjectMapper` field + `Messages.*` imports. Inject any new dependencies needed (e.g. a small cache for last-sent-roster, already present or add as `ConcurrentHashMap<String, Integer>`).

    Keep `@Order(50)` — do not move the tick-pipeline position.
