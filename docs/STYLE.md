# `docs/` — editorial style guide

Standing editorial rules for every doc in `docs/`. Each rule is checkable; new docs and every future edit conform.

| # | Rule | How to VERIFY |
|---|------|---------------|
| **G1** | **EARS §0 clause tables are verbatim, never paraphrased.** A `WHEN … THE SYSTEM SHALL …` clause, its test-method column, and its quoted-assertion column are load-bearing and copied exactly when moved. | `git diff` the §0 block: the WHEN/SHALL rows and the assertion-quote column must be byte-identical pre/post pass. Any change to a §0 row is a spec change, not an editorial trim → out of scope. |
| **G2** | **Every contract claim cites a source `file:line` or a `D-xx`/`T-xx`.** A normative sentence with neither an anchor nor a decision ID is either prose (trimmable) or an unpinned claim (fix by adding the anchor, don't leave floating). | `grep -nE '\.java:[0-9]|application\.yml:|D-[0-9]|T-[0-9]' <doc>` — spot-check that normative sections resolve to anchors. Eyeball: does each contract row carry an anchor or a decision ID? |
| **G3** | **Anchors and decision rationale are preserved across any trim.** Trimming removes PROSE only (restated intros, hedging, redundant re-explanation, narrative). It never removes a `file:line` anchor, a `D-xx`/`T-xx` row, a reversal-table row, a round-trip vector, or a bitmask/byte layout. | `diff` the set of anchors before/after: `grep -oE '[A-Za-z]+\.java:[0-9]+' <doc> \| sort -u` must be a **superset-or-equal** post-trim (never lose one). Same for `grep -oE 'D-[0-9]+' <doc> \| sort -u`. |
| **G4** | **Non-normative narrative is explicitly marked `*(non-normative)*` (or `(Reference)`) and kept ≤ 8 lines, or cut.** Illustrative FSM diagrams, philosophy/rationale asides, and orientation comparisons are marked and bounded; if they exceed the bound they are compressed or deleted, never left as unmarked prose masquerading as contract. | `grep -n 'non-normative\|(Reference)\|(illustrative)' <doc>`; eyeball each marked block is ≤ 8 lines. Unmarked multi-paragraph rationale next to a contract table is a violation. |
| **G5** | **Single-source cross-doc facts; the fuller owner keeps it, the other points.** A fact owned by another doc appears once (in its owner) and elsewhere only as a pointer (`see SCHEMA §8.3`). Named ownerships this pass fixes: WS:entity 1:1 → **HARNESS §1** (ARCHITECTURE/RUNTIME/CLAUDE point); wire-frame grammar → **SCHEMA** (ADMISSION §2 points); backpressure queue-depth math → **ADMISSION §6** (RUNTIME points); firewall *rule* → **CLAUDE.md** (notes point, but keep their per-metric classification tables). | For each owned fact, `grep -rn "<distinctive phrase>" docs/ CLAUDE.md` should return **one** full statement + N pointers, not N copies. |
| **G6** | **No GSD-era process residue in living docs.** Strip `Pass-N Concern #NN`, `gemini R4 finding`, `Round-N … amendment` / `Codex HIGH/MED/LOW … amendment` review-round labels, and `Authored: Phase NN Plan NN` footers — the technical fact survives without the review-process label. **A bare `Plan N` reference is NOT residue** when it carries provenance or a fact (capture dates `Plan 1c — 2026-05-20`, results `Plan 5 confirmed 0 pinning events`, constraints `Plan 5 forbids …`); only an `Authored:`-style attribution footer is. Strip a residue tag even when it sits inside a code-comment, a table row, or an otherwise-frozen ("UNTOUCHED") section — the tag goes, the row/comment/contract stays. | `grep -rniE 'Pass-[0-9]+ Concern\|gemini R[0-9]\|Round [0-9]+ .*amendment\|Codex (HIGH\|MED\|MEDIUM\|LOW)\|Plan [0-9]+ (summary\|attribution)\|Authored: Phase' docs/ \| grep -v '\.planning/\|\.gsd/\|docs/superpowers/'` must return **zero** hits after the pass. The `(summary\|attribution)` group is mandatory so bare load-bearing `Plan N` provenance is NOT falsely flagged; the `Round [0-9]+ .*amendment` / `Codex …` alternates catch the HARNESS L85/L338 review-round residue that the original pattern missed (`Round [0-9]+` cannot false-match `round-trip`, which has no digit). |
| **G7** | **Canonical section numbering and anchors are stable.** Section IDs (`§0`…`§N`, `§8.1.2`) are the addressing scheme other docs and code javadoc cite ("per SCHEMA.md §6"). Trimming a section's prose must not renumber surviving sections. Deleting a whole section (e.g. SCHEMA §11) is allowed only when nothing points to it. | Before deleting/merging a §, `grep -rn "§11\|SCHEMA.*§11" docs/ src/ CLAUDE.md ROADMAP.md BACKLOG.md` to confirm no inbound cite. After the pass, surviving section numbers are unchanged: diff the **numbered-heading list** `grep -nE '^#{1,4} §?[0-9]' <doc>` pre/post. **The `§?` is load-bearing:** SCHEMA headings are `## 5. Frame Inventory` form (digit-first) but RUNTIME/ADMISSION/HARNESS headings are `## §2 Tuning Surface` form (`§`-prefixed) — a bare `^#{1,4} [0-9]` matches ZERO headings in RUNTIME (19) and ADMISSION (10), silently passing vacuously on exactly the doc (RUNTIME §3) that is trimmed hardest; `^#{1,4} §?[0-9]` matches both forms (SCHEMA 32, RUNTIME 19, ADMISSION 10, HARNESS 13). ARCHITECTURE uses prose headings (no `§N`) and carries no source `§N` cite, so its 0-match is tolerable. Any renumber or dropped numbered heading is a G7 violation. |
| **G8** | **Decision-ID (`D-xx`) convention.** Decision IDs are immutable and monotonic per their originating doc/phase; reference them, never renumber or reuse. Rationale attached to a `D-xx` (was/now/reason) is load-bearing (G3). A new decision gets the next free ID, recorded in the doc's reversal/forward-notes table. | `grep -oE 'D-[0-9]+' <doc> \| sort -un` — the set is stable pre/post editorial pass (editorial never mints or drops a D-xx). |
| **G9** | **Keep/trim litmus (the deciding test).** Keep a line if removing it drops a contract, an anchor, a decision rationale, a byte/regex/bit layout, a test vector, or a live coordination breadcrumb. Trim it if it restates CLAUDE.md doctrine, re-explains a sibling doc's contract, recites review process, or hedges/narrates without adding a pinnable fact. When unsure → keep (contracts beat brevity). | Eyeball per candidate line: "does an implementer or a red-line test lose information if this is gone?" If no → trim. If unsure → keep and mark `*(non-normative)*`. |
| **G10** | **Terse, source-referenced, clause-oriented voice.** Match the existing doc voice: no preamble, no puffery, clause/table over paragraph. Do not re-voice or restructure surviving contract sections to taste. | Eyeball: new/edited prose is ≤ the terseness of the surrounding contract text; no adjectival narrative added. |

**GUARDRAIL (restated, binding):** trimming must NOT drop load-bearing content. Every canonical doc
(SCHEMA/ADMISSION/HARNESS/RUNTIME/ARCHITECTURE) survives with its contract intact; EARS §0 clause
tables are preserved verbatim (G1); every `D-xx`/`T-xx`, reversal-table row, round-trip vector,
bitmask/byte layout, and `file:line` anchor is preserved (G3/G8). Project-internal strategic goals
must never appear in any doc.
